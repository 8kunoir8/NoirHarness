## 1. `models.yml` in the profile

### 1.1 Where it lives

`omp --profile noir-spike-two config path` →


So the file is `~/.omp/profiles/<profile>/agent/models.yml` (same directory as `config.yml`,

### 1.2 Exact working YAML

```yaml
providers:
  mock:
    baseUrl: http://127.0.0.1:18081/v1
    api: openai-completions
    apiKey: sk-fake-spike          # fake key; a real one was never used
    models:
      - id: mock-1                 # NOTE: `id`, not `name`, is the required model key
        name: Mock One
        contextWindow: 200000
        maxTokens: 8192
        cost:                      # optional; requires ALL four cost fields
          input: 3                 # USD per 1M input tokens
          output: 15
          cacheRead: 1
          cacheWrite: 2
```

`models` **is a list of model objects**, and the identifier field is **`id`** (a `name` field is
optional display text). Default `reasoning` is `false`; `input` defaults to `["text"]`. **[observed]**

### 1.5 Default model selection

With two models declared in one provider (`zeta-1` first), `session/new` returns:

```json
{"id":"model","name":"Model","category":"model","type":"select",
 "currentValue":"mock/zeta-1",
 "options":[{"value":"mock/zeta-1","name":"Zeta","description":"mock/zeta-1"},
            {"value":"mock/alpha-2","name":"Alpha","description":"mock/alpha-2"}]}
```

* Default = **first declared model** (`zeta-1`), and `options` keeps declaration order
  (note `omp models` sorts alphabetically — do not use that output to predict the default). **[observed]**
* `config.yml` root `model:` is not a setting at all — `omp config get model` →
  `Unknown setting: model`; writing it anyway plus `modelRoles: {main: mock/alpha-2}` did **not**
  change the selection. So do not rely on config.yml to pick the ACP default; read
  `configOptions[id=model].currentValue`. **[observed]**
* `--model` overrides it. Both orders work, and provider-qualified selectors work:

```bash
omp --profile noir-spike-mock --model mock-1        acp   # currentValue mock/mock-1
omp --profile noir-spike-mock acp --model mock-1          # same
omp --profile noir-spike-mock --model mock/mock-1   acp   # same
omp --profile noir-spike-mock --model does-not-exist acp  # session/new still OK, prompt fails, see §6
```

`--model does-not-exist` is accepted silently at `session/new` (the model option still lists
`mock/mock-1`), but the first `session/prompt` returns `-32603` + `"No model selected."` — i.e. an
invalid `--model` **poisons the session** rather than failing fast. **[observed]**

## 3. Prompt streaming

Request:

```json
--> {"jsonrpc":"2.0","id":3,"method":"session/prompt","params":{"sessionId":"01a1c298-5b04-74d2-b2eb-e9998c07d101","prompt":[{"type":"text","text":"Say hello."}]}}
```

Mock provider was scripted to emit three content deltas: `"Hel"`, `"lo from "`, `"mock."`.

Every notification for the turn (verbatim, `available_commands_update` elided):

```json
<-- {"method":"session/update","params":{"sessionId":"…","update":{"sessionUpdate":"session_info_update","updatedAt":"2026-11-09T23:15:27.108Z"}}}
<-- {"method":"session/update","params":{"sessionId":"…","update":{"sessionUpdate":"agent_message_chunk","content":{"type":"text","text":"Hel"},"messageId":"74534f0c-7858-47fc-bf55-4d0a9b031f40"}}}
<-- {"method":"session/update","params":{"sessionId":"…","update":{"sessionUpdate":"agent_message_chunk","content":{"type":"text","text":"lo from "},"messageId":"74534f0c-7858-47fc-bf55-4d0a9b031f40"}}}
<-- {"method":"session/update","params":{"sessionId":"…","update":{"sessionUpdate":"agent_message_chunk","content":{"type":"text","text":"mock."},"messageId":"74534f0c-7858-47fc-bf55-4d0a9b031f40"}}}
<-- {"method":"session/update","params":{"sessionId":"…","update":{"sessionUpdate":"usage_update","size":200000,"used":11}}}
<-- {"method":"session/update","params":{"sessionId":"…","update":{"sessionUpdate":"session_info_update","updatedAt":"2026-11-09T23:15:28.303Z"}}}
<-- {"jsonrpc":"2.0","id":3,"result":{"stopReason":"end_turn","usage":{"inputTokens":11,"outputTokens":7,"totalTokens":18}}}
```

Conclusion:

* **One `session/update` per provider delta.** Chunk boundaries are not merged — the adapter must
  concatenate. All chunks of one assistant message share one `messageId` (random UUIDv4 per
  assistant message, regenerated when the next assistant message starts). **[observed]**
* Ordering per turn: `agent_message_chunk`* → (`tool_call`/`tool_call_update`)* → … →
  `usage_update` → `session_info_update` → prompt **response**. **[observed]**
* `agent_thought_chunk` is identical in shape and shares the same `messageId` as the following
  `agent_message_chunk` when the model streams reasoning (mock emitted
  `delta.reasoning_content`): **[observed]**

```json
{"sessionUpdate":"agent_thought_chunk","content":{"type":"text","text":"Let me "},"messageId":"ff19cf9f-c0af-44a2-affd-a01a9d77211f"}
{"sessionUpdate":"agent_thought_chunk","content":{"type":"text","text":"think."},"messageId":"ff19cf9f-c0af-44a2-affd-a01a9d77211f"}
{"sessionUpdate":"agent_message_chunk","content":{"type":"text","text":"Final answer."},"messageId":"ff19cf9f-c0af-44a2-affd-a01a9d77211f"}
```

* `usage_update` = `{size, used}` (context window and context tokens); `cost` appears **only when
  cost > 0**, as `{"amount":0.0105,"currency":"USD"}` — observed with the 4-field `cost` in
  `models.yml` and a 1000-in/500-out turn:

```json
{"sessionUpdate":"usage_update","size":200000,"used":1000,"cost":{"amount":0.0105,"currency":"USD"}}
```

* The prompt result's `usage` is the **delta for the turn** and is **omitted entirely when
  `totalTokens` did not change** (seen in the cancel and reject runs). Keys are
  `inputTokens`, `outputTokens`, `totalTokens`, plus `cachedReadTokens`/`cachedWriteTokens` only when non-zero. **[observed]**
* `session/prompt` does **not** validate prompt blocks: `prompt: []` and `prompt:[{"type":"text"}]`
  both ran a turn with empty text instead of returning an error. Only the non-standard
  `_session/steering` ext method validates. **[observed]**
* `messageId` is absent on `usage_update`/`session_info_update`; do not require it. **[observed]**

What omp sends upstream (for debugging the mock): first turn is
`POST /v1/chat/completions` with `stream:true`, `store`, `stream_options`,
`max_completion_tokens`, `reasoning_effort` (reasoning models only), 11 `tools`
(`read, bash, edit, eval, glob, grep, task, wait, todo, web_search, write`) and messages
`[system, user]` where the user content is an array of `{type:"text"}` blocks. **[observed]**

## 4. Tool call + permission

Mock returned an OpenAI tool call `bash({"command":"echo hi"})`. Flow (client advertises
`terminal:true` and `fs.*`):

### 4.1 Agent → client: `session/request_permission` (verbatim)

```json
<-- {"jsonrpc":"2.0","id":0,"method":"session/request_permission","params":{
      "sessionId":"01a1c298-61af-7512-b3a1-62a5f7455986",
      "toolCall":{"toolCallId":"call_mock_1","title":"echo hi","kind":"execute","status":"pending",
                  "rawInput":{"command":"echo hi"},
                  "content":[{"type":"content","content":{"type":"text","text":"$ echo hi"}}],
                  "locations":[]},
      "options":[{"optionId":"allow_once","name":"Allow once","kind":"allow_once"},
                 {"optionId":"allow_always","name":"Always allow","kind":"allow_always"},
                 {"optionId":"reject_once","name":"Reject","kind":"reject_once"},
                 {"optionId":"reject_always","name":"Always reject","kind":"reject_always"}]}}
```

* `toolCall` carries **no `name` field** — only `title` (for bash it is the command sliced to 80
  chars, *without* the `$ ` prefix used in updates), `kind`, `status`, `rawInput`, `content`
  (1 text part `"$ <command>"`) and `locations` (empty array for bash). **[observed]**
* The four `options` are fixed (source constant): `allow_once/Allow once`, `allow_always/Always
  allow`, `reject_once/Reject`, `reject_always/Always reject`. **[observed]**
* Request id from the agent starts at **0** and counts up in its own id space (the client's ids are
  separate). **[observed]**
* Ordering, observed: `session/request_permission` arrives **before** the matching `tool_call`
  update (and before `terminal/create`), i.e. an adapter cannot wait for `tool_call` before showing
  the prompt — render it from `params.toolCall`. Only one request per tool call. **[observed]**

  ```text
  130.009  req  session/request_permission id 0
  130.010  resp {"outcome":{"outcome":"selected","optionId":"allow_once"}}
  130.017  upd  tool_call                       pending     call_mock_1
  130.018  req  terminal/create                 id 1
  130.275  upd  tool_call_update                in_progress call_mock_1
  130.276  upd  tool_call_update                completed   call_mock_1
  130.291  upd  agent_message_chunk
  130.300  upd  usage_update / session_info_update
  130.300  resp session/prompt id 3             {"stopReason":"end_turn", …}
  ```

### 4.2 Client → agent reply (accepted)

```json
--> {"jsonrpc":"2.0","id":0,"result":{"outcome":{"outcome":"selected","optionId":"allow_once"}}}
```

Cancel/dismiss is `{"outcome":{"outcome":"cancelled"}}`. **[source]** for the alternate arm;
`selected` observed.

### 4.3 Agent → client: `terminal/*` (because `terminal:true`)

```json
<-- {"id":1,"method":"terminal/create","params":{
      "sessionId":"…","command":"C:\\Program Files\\Git\\bin\\bash.exe","args":["-l","-c","echo hi"],
      "env":[{"name":"PI_SESSION_ID","value":"…"},
             {"name":"PI_SESSION_FILE","value":"…\\noir-spike-mock\\agent\\sessions\\-tmp-acpspike-work\\2026-11-09T23-15-28-815Z_….jsonl"},
             {"name":"PI_TOOL_CALL_ID","value":"call_mock_1"}],
      "cwd":"C:\\Users\\Steru\\AppData\\Local\\Temp\\acpspike\\work","outputByteLimit":51200}}
--> {"id":1,"result":{"terminalId":"term-1"}}
<-- {"id":2,"method":"terminal/wait_for_exit","params":{"sessionId":"…","terminalId":"term-1"}}
--> {"id":2,"result":{"exitCode":0,"signal":null}}
<-- {"id":3,"method":"terminal/output","params":{"sessionId":"…","terminalId":"term-1"}}
--> {"id":3,"result":{"output":"hi\n","truncated":false,"exitStatus":{"exitCode":0,"signal":null}}}
<-- {"id":4,"method":"terminal/release","params":{"sessionId":"…","terminalId":"term-1"}}
```

Deviations from the ACP spec the adapter must tolerate: **`env` is an array of `{name,value}`**, not
an object; the shell command is `bash.exe -l -c "<command>"` on this machine. If the client replies
`{}` to `terminal/create` (no `terminalId`), omp keeps going with `terminalId` undefined, calling
`terminal/wait_for_exit` / `terminal/output` with `{sessionId}` only, and the tool then fails with
`"undefined is not an object (evaluating 't.startsWith')"` — so always return a `terminalId`. **[observed]**

### 4.4 Updates for the tool call (verbatim, in order)

```json
{"sessionUpdate":"tool_call","toolCallId":"call_mock_1","name":"bash","title":"$ echo hi","kind":"execute",
 "status":"pending","rawInput":{"command":"echo hi"},
 "content":[{"type":"content","content":{"type":"text","text":"$ echo hi"}}]}

{"sessionUpdate":"tool_call_update","toolCallId":"call_mock_1","status":"in_progress",
 "rawOutput":{"content":[],"details":{"terminalId":"term-1"}},
 "content":[{"type":"content","content":{"type":"text","text":"$ echo hi"}},
            {"type":"terminal","terminalId":"term-1"}]}

{"sessionUpdate":"tool_call_update","toolCallId":"call_mock_1","status":"completed",
 "rawOutput":{"content":[{"type":"text","text":"hi\n"}],
              "details":{"wallTimeNoticeEmitted":false,"timeoutSeconds":300,"wallTimeMs":257.05}},
 "content":[{"type":"content","content":{"type":"text","text":"$ echo hi"}},
            {"type":"content","content":{"type":"text","text":"hi\n"}},
            {"type":"content","content":{"type":"text","text":"hi"}}]}
```

* `tool_call` comes from `tool_execution_start`, `tool_call_update` from
  `tool_execution_update` (`status:"in_progress"`) and `tool_execution_end`
  (`status:"completed"` or `"failed"`). **[source]** names the emitters; shapes **[observed]**.
* Content parts are `{type:"content", content:{type:"text"|"image"|"audio"|"resource_link"|"resource"}}`
  plus a non-schema `{type:"terminal", terminalId}` part that omp itself emits. **[observed]**
* `kind` mapping **[source]**: `read`→read, `write`/`edit`→edit, `delete`→delete, `move`→move,
  `bash`/`shell`/`exec`/`eval`→execute, `grep`/`glob`/`ast_grep`→search, `web_search`→fetch,
  `todo`→think, else other.
* Duplicate tool-call ids from the model are de-duplicated by suffixing: the second and later ones
  arrive as `call_mock_1_dup1`, `call_mock_1_dup193`, … (observed while the mock kept replaying the
  same id). Adapter must treat `toolCallId` as opaque. **[observed]**
* `todo` tool results additionally emit a `plan` update (`{sessionUpdate:"plan", entries:[{content, priority:"medium", status}]}`). **[source]**

## 5. Cancellation and close

### 5.1 `session/cancel` (notification, no response)

Mid-turn (`chunk_delay_ms: 700`, cancel sent 1.6 s in):

```json
--> {"jsonrpc":"2.0","method":"session/cancel","params":{"sessionId":"…"}}
<-- {"id":3,"result":{"stopReason":"cancelled"}}          // 1.62 s after the prompt, ~0.02 s after cancel
```

Chunks already streamed stay delivered (`"one "`, `"two "`); no `usage` in the result. **[observed]**

### 5.2 Cancel is the escape hatch for a hung provider

With the mock server **down** the prompt never resolved (73 s, no error frame). Sending
`session/cancel` 3 s in resolved it immediately:

```json
{"jsonrpc":"2.0","id":3,"result":{"stopReason":"cancelled"}}   // elapsed 3.02 s
```

with no other updates than `session_info_update`. **[observed]** → the adapter *must* own the turn
timeout and cancel, because `session/prompt` has no deadline of its own.

### 5.3 `session/close`

```json

<-- {"id":4,"result":{}}
```

## 6. Failure shapes

### 6.1 No usable credentials / no model (`mocknk` provider without `apiKey`, and `--model does-not-exist`)

`session/new` succeeds but `configOptions` **has no `model` entry** (`mode`, `thinking` only). Every
prompt fails immediately:

```json
<-- {"jsonrpc":"2.0","id":3,"error":{"code":-32603,"message":"Internal error","data":{"details":
     "No model selected.\n\nUse /login, set an API key environment variable, or create C:\\Users\\Steru\\.omp\\profiles\\noir-spike-nokey\\agent\\agent.db\n\nThen use /model to select a model."}}}
```

### 6.2 Unknown session vs unknown method

```json
{"error":{"code":-32002,"message":"Resource not found: nope","data":{"uri":"nope"}}}   // session/prompt on closed/unknown session
{"error":{"code":-32603,"message":"Internal error","data":{"details":"Unknown ACP ext method: session/bogus"}}}
```

Note the second one: an unknown **request** method is routed to `extMethod` and comes back as
`-32603` (not `-32601`). `-32601` is only produced by omp for unknown methods *it* sends to the client. **[observed]**

Other observed `-32603 + data.details` messages: `"ACP cwd must be absolute: work"`,
`"Unsupported ACP mode: bogus"`, `"Unknown ACP config option: bogus"`. **[observed]**

### 6.3 Provider unreachable (connection refused)

No ACP error and no `session/update` error text: the turn stays open (≥73 s observed, retry/backoff
loop). Only `session/cancel` ends it (§5.2). **[observed]**

### 6.4 Provider returns HTTP 500

11 upstream attempts inside the first 8.0 s (mock logged 11 `POST /v1/chat/completions`, all answered
500), then no further requests — and the prompt was still pending when the probe gave up at 75 s.
Same conclusion: no ACP-level error frame, adapter timeout + cancel required. **[observed]**

> Design note for the adapter: treat "prompt pending longer than N seconds with no
> `agent_message_chunk`/`tool_call`/`usage_update`" as a provider stall → `session/cancel` and
> surface a local error. omp will not report provider connectivity failures during a turn over ACP.

### 6.5 Session busy (not exercised)

**[source]** `session/prompt` uses an internal queue; the only busy-shaped error is
`-32003 sessionBusy` with `data:{reason:"session_busy", hint:"steer|followUp|wait"}`, thrown when a
custom-message path rejects. Treat as "may appear; retry after the current turn settles".

## 7. Adapter contract

Minimum client behaviour for NoirHarness ↔ `omp --profile <p> acp`.

### 7.1 Framing

* Write one **compact** JSON object per line to stdin, flush each line.
* Read stdout line-by-line with an **unbounded-but-chunked** buffer: single frames can reach
  ~25 KB (`available_commands_update`).
* stderr is log output only (omp redirects `console.log` there); never parse it for protocol data.
* JSON-RPC id spaces are per-direction; the agent's own requests start at `id: 0`.

### 7.2 Methods the adapter MUST send

| method | params | result / notes |
| --- | --- | --- |
| `initialize` | `{"protocolVersion":1,"clientCapabilities":{"fs":{"readTextFile":true,"writeTextFile":true},"terminal":true}}` | `protocolVersion`, `agentInfo`, `authMethods[{id:"agent"}]`, `agentCapabilities.sessionCapabilities{list,fork,resume,close}`, `_meta.steering.supported`. Do not expect model info here. |
| `session/new` | `{"cwd":"<absolute path>","mcpServers":[]}` | `{sessionId, configOptions[mode, model?, thinking], modes:{availableModes,currentModeId}}`. Relative `cwd` ⇒ `-32603`. |
| `session/prompt` | `{"sessionId","prompt":[{"type":"text","text"}]}` | `{stopReason, usage?}`. `stopReason ∈ end_turn \| cancelled \| max_tokens \| max_turn_requests \| refusal`. `usage` only when tokens moved. |
| `session/cancel` (**notification**) | `{"sessionId"}` | no response; the in-flight `session/prompt` resolves `{"stopReason":"cancelled"}`. Required for timeouts. |
| `session/close` | `{"sessionId"}` | `{}` (also for unknown ids). Afterwards any request on that id ⇒ `-32002`. |
| `session/set_config_option` | `{"sessionId","configId":"model"\|"thinking"\|"mode","value"}` | `{configOptions}`. This is **the** model-selection path (value `"provider/modelId"`). Unknown id ⇒ `-32603`. |
| `session/set_mode` | `{"sessionId","modeId":"default"\|"plan"}` | `{}`, then `current_mode_update` + `config_option_update` notifications. |
| `session/list` / `session/fork` / `session/resume` / `session/load` | as ACP | advertised; `list`/`fork` observed working. `load`/`resume` untested. |
| `authenticate` | `{"methodId":"agent"}` | only needed if you want to be spec-correct after choosing `authMethods[0]`; returns `{}`. **[source]** |
| ext (optional) | `speech.models.list`, `_omp/sessions/listAll`, `_omp/projects/list`, `_omp/chats/byCwd`, `_omp/usage`, `_omp/extensions`, `_omp/extensions/toggle`, `_session/steering` | **[source]**; not needed for M1.1. |

### 7.3 Requests the adapter MUST answer (agent → client)

| method | params | reply |
| --- | --- | --- |
| `session/request_permission` | `{sessionId, toolCall:{toolCallId,title,kind,status,rawInput,content,locations}, options:[{optionId,name,kind}]}` | `{"outcome":{"outcome":"selected","optionId":"allow_once"\|"allow_always"\|"reject_once"\|"reject_always"}}` or `{"outcome":{"outcome":"cancelled"}}` |
| `fs/read_text_file` (if advertised) | `{sessionId,path,line?,limit?}` | `{content:"<text>"}` **[source]** |
| `fs/write_text_file` (if advertised) | `{sessionId,path,content}` | `{}` **[source]** |
| `terminal/create` (if advertised) | `{sessionId,command,args,env:[{name,value}],cwd,outputByteLimit}` | `{terminalId}` — always return an id |
| `terminal/output` | `{sessionId,terminalId}` | `{output,truncated,exitStatus:{exitCode,signal}\|null}` |
| `terminal/wait_for_exit` | `{sessionId,terminalId}` | `{exitCode,signal}` |
| `terminal/kill`, `terminal/release` | `{sessionId,terminalId}` | `{}` |
| `elicitation/create` (only if `clientCapabilities.elicitation.form` set) | form schema | `{action:"accept"\|"cancel"\|"decline", content?}` **[source]** |

Cheapest viable M1.1 configuration: advertise `fs.readTextFile` + `fs.writeTextFile` + `terminal`
so omp never falls back to in-process file/shell work; if you would rather not implement terminals,
omit `terminal` from `clientCapabilities` **[inferred]** — omp then executes bash in-process
(not verified in this spike).

### 7.4 `session/update` kinds to handle

`params = {sessionId, update:{sessionUpdate, …}}`.

| `sessionUpdate` | payload (beyond `sessionUpdate`) | must handle? |
| --- | --- | --- |
| `agent_message_chunk` | `content:{type:"text"\|"image",…}`, `messageId` | yes — append by `messageId` |
| `agent_thought_chunk` | same shape, same `messageId` as the following message chunks | yes — render separately |
| `tool_call` | `toolCallId,name,title,kind,status,rawInput,content?,locations?` | yes |
| `tool_call_update` | `toolCallId,status:"pending"\|"in_progress"\|"completed"\|"failed",rawOutput,content?,locations?` | yes |
| `plan` | `entries:[{content,priority,status}]` | recommended |
| `current_mode_update` | `currentModeId` | recommended |
| `config_option_update` | `configOptions[]` | recommended (model/thinking changed) |
| `available_commands_update` | `availableCommands[]` (~25 KB) | yes — must not choke |
| `session_info_update` | `title?`, `updatedAt` | yes (title may be absent) |
| `usage_update` | `size`, `used`, `cost?:{amount,currency}` | yes |
| `user_message_chunk` | only during `session/load` replay | if you support load |

The adapter must also tolerate update kinds it does not know (ignore unknown `sessionUpdate`
values), and content parts `{type:"terminal"}`.

### 7.5 Error mapping

| JSON-RPC error | meaning / action |
| --- | --- |
| `-32603` + `data.details` string | generic agent failure. Notable details: `"No model selected. …"`, `"ACP cwd must be absolute: …"`, `"Unsupported ACP mode: …"`, `"Unknown ACP config option: …"`, `"Unknown ACP ext method: …"` |
| `-32002` `Resource not found: <id>` `data.uri` | session id gone (closed/never existed) |
| `-32003` with `data.reason="session_busy"` | busy; retry after the current turn settles **[source]** |
| `-32800` `Request cancelled` | only for `$/cancel_request` handling **[source]** |
| `-32601` | never emitted by omp for unknown inbound methods; it answers `-32603` instead |
| pending prompt with no updates | provider stall (connection refused / 5xx / no credentials during turn) → local timeout + `session/cancel` |

### 7.6 Practical rules

1. Always send an absolute `cwd`; a relative one is a hard `-32603`.
2. Read the model list from `session/new.configOptions[id=="model"].options`; there is no
   `session/models` method. If the `model` option is missing, the profile has no usable model
   (often an invalid `models.yml`) — surface that before prompting.
3. Choose/switch models with `session/set_config_option` (`configId:"model"`, `value:"provider/model"`).
4. Keep a per-turn watchdog: `session/prompt` may never return on provider failures; `session/cancel`
   resolves it with `stopReason:"cancelled"`.
5. Expect a randomised duplicate suffix on `toolCallId` (`_dup1`, …); key everything by the id you
   last saw on `tool_call`.
6. Answer `session/request_permission` synchronously — omp blocks the tool call until you reply.
7. Do not rely on `usage_update`/`usage` existing; both are conditional on token/cost deltas.
8. Buffer whole lines; the first notification after `session/new` can be tens of kilobytes.
