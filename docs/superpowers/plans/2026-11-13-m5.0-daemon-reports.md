# M5.0 Implementation Plan

**Goal:** a scheduled run nobody is watching announces itself, a dead kernel is restarted, and the kernel can start with the machine.

**Spec:** `docs/superpowers/specs/2026-11-13-m5.0-daemon-reports-design.md`

## Global Constraints

- Node >= 24 / Electron 38 (Node 22 in main, global `WebSocket`), TS strict, ESM `.js` imports, zero new runtime dependencies.
- One commit per task on `main`; never branch, never push, never amend.
- Never log a prompt or a cookie; the notification body carries a title and a failure message only.
- Targeted suites per task; one full gate at the end against the **947 unit / 17 e2e** baseline.

---

### Task 1: `session.created` says which schedule fired it

**Files:** `packages/protocol/src/events.ts`, `packages/kernel/src/sessions.ts`, `packages/kernel/test/sessions.test.ts`

Payload gains `scheduleId: z.string().optional()`. `SessionService.create` passes the row's.

**Verification:** `pnpm exec vitest run test/sessions.test.ts` — a scheduled session's event carries the id; an interactive one does not.

---

### Task 2: The witness

**Files:** `apps/desktop/src/notifications.ts` (pure), `apps/desktop/test/notifications.test.ts`

```ts
export interface NotificationSink { show(title: string, body: string): void }
export class ScheduleWatcher {
  constructor(sink: NotificationSink)
  observe(event: AgentEvent): void          // raises at most one notification per run
  sessions(): readonly string[]              // for the tests
}
```

Only `session.created` (with `scheduleId`), `turn.completed` and `turn.failed` are inspected; everything else is ignored without allocation.

**Verification:** `pnpm exec vitest run test/notifications.test.ts` — the cases in the spec.

---

### Task 3: Wire the witness and the supervisor into main

**Files:** `apps/desktop/src/kernelEvents.ts` (socket client), `apps/desktop/src/supervision.ts` (health polling), `apps/desktop/src/main.ts`, `apps/desktop/test/supervision.test.ts`

`kernelEvents.ts` opens `ws://127.0.0.1:<port>/?token=…`, reconnects with backoff, feeds `ScheduleWatcher`, and writes a line to `NOIR_NOTIFY_LOG` when that env var is set. `supervision.ts` owns the timer and the respawn decision, injected with `probe`, `respawn`, `now` so it is testable without Electron.

**Verification:** `pnpm exec vitest run test/supervision.test.ts` — threshold, rate limit, pid adoption.

---

### Task 4: Start at login

**Files:** `apps/desktop/src/settings.ts`, `apps/desktop/src/tray.ts`, `apps/desktop/src/main.ts`, `apps/desktop/test/settings.test.ts`, `apps/desktop/test/tray.test.ts`

`readSettings/writeSettings` over `<dataDir>/desktop.json`; tray gains a checkbox item; main applies the stored value once at launch.

**Verification:** `pnpm exec vitest run test/settings.test.ts test/tray.test.ts`.

---

### Task 5: E2E, docs, gate

**Files:** `apps/desktop/test/automations.spec.ts`, `apps/desktop/test/app-harness.ts`, `README.md`

The fire e2e sets `NOIR_NOTIFY_LOG` and asserts the finished line appears after the run completes.
Not `daemon-fire.spec.ts`: that spec quits the app before the fire, and the notification is raised by
the app process, which the harness deliberately takes away. `automations.spec.ts` already fires a real
schedule with the app alive, so it is the honest place for the assertion; the windowless fire stays
proven by the run row and the panel.

**Verification:** `pnpm exec playwright test test/daemon-fire.spec.ts --reporter=line`, then `pnpm -r typecheck`, `pnpm -r test`, `pnpm test:e2e`.
