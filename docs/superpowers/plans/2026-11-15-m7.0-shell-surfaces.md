# M7.0 Shell Surfaces — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Menus on every object, a Source page that stages and commits, a Help page that tells the truth about keys and version, and an update notice that cannot block anything.

**Architecture:** One renderer-drawn `ContextMenu` provider that every surface feeds through its own `menuItemsFor(target)`; kernel-side git mutations that serialize per workspace and return the fresh status; a Help view generated from the command registry; a kernel-side update policy that owns cadence and dismissal and speaks only through `update.check` / `update.dismiss`.

**Tech Stack:** Electron 3x (frameless main window), React 19 renderer, TypeScript strict, zod over a WebSocket JSON-RPC kernel (`packages/kernel`), better-sqlite3, Playwright + vitest.

**Spec:** `docs/superpowers/specs/2026-11-15-m7.0-shell-surfaces-design.md`

## Global Constraints

- Node >= 24, pnpm >= 10, TS strict with `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes`; ESM with `.js` specifiers. No `: any`, no `as any`.
- One commit per change set on `main`; never branch, push, or amend. Commit messages via `write` to `.superpowers/commit-msg.txt`, then `git commit -F .superpowers/commit-msg.txt`.
- Source edits only through the `edit` tool; no `sed`/`perl`/`python` rewrites of source.
- Optional callbacks are written `onX?: ((a: A) => void) | undefined`; passing `undefined` explicitly requires the `exactOptionalPropertyTypes` spread idiom.
- No one-expression wrapper functions unless the wrapper is a durable contract.
- `.probe/` and `.superpowers/` are scratch; never commit them.
- Every RPC result change is additive: `GitFileStatus.change/add/del` keep their current meaning, `GitStatusView.files` keeps one row per path.

## Review Focus

| Input or condition | What a reasonable person expects |
|---|---|
| A menu opened at the window's right or bottom edge | It flips to stay on screen, not clipped |
| A file that is both staged and modified | It appears in both Source groups, and the checkbox in each does the right thing |
| A commit hook that rejects, or hangs | The hook's own words appear inline; a hang ends in an error, never a spinner |
| Two windows, or two commits in flight | One order, never an interleaved index; the second commit sees the first |
| A private repo with no cached credentials during the update check | Nothing on screen changes and nothing blocks; Help can say why |
| A repository with no commits yet | Unstage works, not `fatal: ambiguous argument 'HEAD'` |

```ts
export interface Shortcut {
  key: string;
  /** Command/Control on every platform; the shell is Windows-first but must not fight macOS. */
  mod?: boolean;
  shift?: boolean;
  /** Alt/Option. Compared exactly: an event's alt must match the shortcut's. */
  alt?: boolean;
}

/** Read once at module load; a test passes the platform instead of mutating the runtime. */
const DEFAULT_PLATFORM = typeof navigator === "undefined" ? "win32" : navigator.platform;

export function shortcutKey(shortcut: Shortcut): string {
  const parts = [
    shortcut.mod === true ? "mod" : "",
    shortcut.shift === true ? "shift" : "",
    shortcut.alt === true ? "alt" : "",
    shortcut.key.toLowerCase(),
  ].filter((part) => part !== "");
  return parts.join("+");
}

/**
 * `Ctrl+Shift+K` on the platform this app ships for, `⌘⇧K` on macOS. The glyph form is a macOS
 * convention; printing it on Windows taught the wrong key.
 */
export function shortcutLabel(shortcut: Shortcut, platform: string = DEFAULT_PLATFORM): string {
  const key = shortcut.key.length === 1 ? shortcut.key.toUpperCase() : shortcut.key.toUpperCase();
  if (platform.startsWith("darwin") || platform.startsWith("Mac")) {
    return `${shortcut.mod === true ? "⌘" : ""}${shortcut.alt === true ? "⌥" : ""}${
      shortcut.shift === true ? "⇧" : ""
    }${key}`;
  }
  const parts = [
    shortcut.mod === true ? "Ctrl" : "",
    shortcut.alt === true ? "Alt" : "",
    shortcut.shift === true ? "Shift" : "",
    key,
  ].filter((part) => part !== "");
  return parts.join("+");
}

export function matchesShortcut(event: KeyboardEvent, shortcut: Shortcut): boolean {
  if (event.key.toLowerCase() !== shortcut.key.toLowerCase()) return false;
  const mod = event.metaKey || event.ctrlKey;
  if (mod !== (shortcut.mod === true)) return false;
  if ((event.shiftKey === true) !== (shortcut.shift === true)) return false;
  return (event.altKey === true) === (shortcut.alt === true);
}
```

- [ ] **Step 4: Implement the mutations**

`GIT` and `run` already exist. Add `MUTATE_TIMEOUT_MS = 30_000` and a `gitMutate(root, args)` clone of `git` that uses it. Serialization:

```ts
const chains = new Map<string, Promise<unknown>>();

/** One mutating git command at a time per workspace: RPC handlers are concurrent, index writes are not. */
function serialize<T>(root: string, action: () => Promise<T>): Promise<T> {
  const previous = chains.get(root) ?? Promise.resolve();
  const next = previous.then(action, action);
  chains.set(root, next.catch(() => undefined));
  return next;
}
```

`gitStage`: `serialize(root, …)` → resolve every path with `resolveInsideRoot` (throws the guard's fault) → one `git add -- <paths>`; deleted paths are already covered by `git add` with `-A` semantics in modern git, so pass `--` only and verify with the test.

`gitUnstage`: `git reset -q HEAD -- <paths>`, and when that fails with `ambiguous argument 'HEAD'` (no commit yet) fall back to `git rm --cached -q -- <paths>`.

`gitCommit`: trim, reject empty with `RpcFault(ErrorCodes.invalidParams, "Write a commit message")`; read status first and reject with `RpcFault(ErrorCodes.conflict, "Nothing staged to commit")` when no file has `index !== null`; then `git commit -m <message>` inside `serialize`, with `GIT_TERMINAL_PROMPT=0` in the env; `sha` from `git rev-parse HEAD`, `summary` from `git log -1 --pretty=%s`. Git's stderr goes into the fault message verbatim, because a hook rejection is the user's information.
