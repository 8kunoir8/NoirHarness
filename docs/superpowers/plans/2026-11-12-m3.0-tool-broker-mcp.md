# M3.0 Tool Broker (MCP Client) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local Tool Broker implementing the Model Context Protocol (MCP) client over `stdio`, connecting external tool servers into both Native and ACP engines with agent permission governance.

**Architecture:** The kernel manages registered MCP servers in SQLite (`mcp_servers` table). A lightweight in-tree JSON-RPC 2.0 stdio client handles process execution, protocol handshakes, and tool invocation. Discovered tools are namespaced (`mcp__<serverName>__<toolName>`) and injected into the Native engine's tool loop and ACP's `session/new` payload. Agent permission policies govern MCP calls via a new `"mcp"` category.

**Tech Stack:** TypeScript strict ESM, Node.js `child_process.spawn`, SQLite (via `better-sqlite3`), Zod, React, Electron, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-11-m3.0-tool-broker-mcp-design.md`

## Global Constraints

- Node >= 24, pnpm >= 10, TypeScript strict with `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes`; ESM with `.js` import extensions; Windows-first.
- One commit per task on `main`. Never create a branch, never push.
- Kernel is the single authority for process execution and database persistence; every RPC validates parameters with Zod first.
- Tool naming convention: `mcp__<serverName>__<toolName>` strictly enforced.
- Keep all existing labels and testids: `kernel-status`, `session-status`, `message-assistant`, `tool-card`, `permission-card`, nav `Chats`/`Setup`/`Agents`.
- Zero new runtime npm dependencies; lightweight in-tree framing for stdio JSON-RPC.

## Review Focus

1. **Non-JSON stdout on stdio**: Server prints non-JSON warnings or banner to stdout; parser must skip malformed lines without breaking JSON-RPC framing (tested in Task 3).
2. **Subprocess crash before handshake**: Executable fails on start (e.g. `ENOENT` / command not found); client must catch spawn error and return clean failure within 10 s rather than hanging (tested in Task 3).
3. **Empty tool list**: Connected server advertises zero tools; broker cleanly exposes 0 tools without throwing or failing session startup (tested in Task 4).
4. **Tool execution timeout**: A tool call stalls; watchdog aborts after timeout, cleans up pending promise, and emits `tool.failed` (tested in Task 3 and Task 5).
5. **Special characters & nested JSON args**: Unicode, double quotes, and nested arrays in tool arguments pass faithfully through the JSON-RPC boundary (tested in Task 3 and Task 5).
