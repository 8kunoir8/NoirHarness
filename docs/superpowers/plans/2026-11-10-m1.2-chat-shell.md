# M1.2 — Chat shell

Goal: the app becomes a usable agent workspace — rail, session list, tabs, a chat surface with
model/usage/turn state, a composer that shows queue and interrupt, an inspector, and a command
palette. Every action is a kernel RPC first; the renderer never talks to an engine directly.

Exit criterion (spec §13): full session lifecycle visible and controllable.

## Non-goals

- Editor, file tree, Monaco, diffs, git — M1.3.
- Skill registry and viewer — M1.4.
- Agents roster (multi-agent), Office view, native engine — later milestones.
- Provider/model CRUD stays on the Setup page; the shell only lists models for picking.

## Constraints carried from M1.0/M1.1

- Renderer is a pure consumer: WebSocket JSON-RPC + events, no Node, no secrets.
- Keys never appear in RPC results, events, logs, or renderer state.
- `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes` are on; no `any` in renderer code.
- Events are append-only with per-session `seq`; the reducer must stay replay-safe and idempotent.
- Accessibility is not optional: semantic landmarks, `aria-pressed`/`aria-label`, visible focus,
  full keyboard operation, WCAG AA contrast in both themes.

## Decisions

1. **One shell, four regions.** `AppShell` is `rail | list | main | inspector` plus a top bar and a
   status bar. Chat is a tab inside `main`; Setup stays a separate top-level view until a model
   exists (first-run).
2. **Session list is kernel data.** Filters need "needs you" and recency, which the renderer cannot
   derive without subscribing to every session. `session.list` gains per-session `lastEventSeq`,
   `lastEventAt`, and `pendingApproval`; the list pane filters on them.
3. **Model switching is a kernel RPC.** `session.setModel` validates the model against the enabled
   registry, updates `sessions.model_id`, and lets the existing engine path apply it on the next
   turn (`session/set_config_option` when the selector changes). No engine restart.
4. **Themes are CSS custom properties** on `:root[data-theme="paper"|"ink"]`. No utility framework,
   no runtime CSS-in-JS. One `styles.css` split into token block + component blocks.
5. **Palette actions call the same RPCs as the buttons.** A single command registry
   (`commands.ts`) exposes `{ id, title, shortcut, run, enabled }`; the palette, keyboard handler,
   and buttons all read from it, so they cannot drift.
6. **Tabs are renderer state, sessions are kernel state.** Open tabs persist per window in
   `localStorage` (ids only); a tab whose session is closed renders as closed and can be dismissed.

## Tasks

### 1. Kernel surface for the shell

Files: `packages/protocol/src/rpc.ts`, `packages/kernel/src/sessions.ts`,
`packages/kernel/src/index.ts`, `packages/kernel/test/sessions*.test.ts`, `apps/desktop/src/renderer/api.ts`.

- `SessionView` gains `lastEventSeq: number`, `lastEventAt: number`, `pendingApproval: boolean`.
  `SessionService.list()` computes them with two grouped queries over `events`
  (`MAX(seq)`, `MAX(ts)`, and the last `permission.requested` / `permission.resolved` row per session).
- New `session.setModel` params `{ sessionId, modelId }` → returns `SessionView`. Rejects unknown,
  disabled, or provider-disabled models and closed sessions with the same errors `session.create` uses.
- Kernel test: list metadata reflects appends; `setModel` rejects a disabled model and updates the row.

### 2. AppShell, tokens, rail, list, status bar

Files: `apps/desktop/src/renderer/App.tsx`, new `Shell.tsx`, `Rail.tsx`, `SessionList.tsx`,
`StatusBar.tsx`, `styles.css`, `apps/desktop/test/shell.test.tsx`.

- `data-theme` on `<html>`; `paper` (default) and `ink`; toggle in the top bar, persisted.
- Rail items: Chats, Setup (settings), theme toggle; `aria-current` on the active one.
- List pane: search field, filter chips `All / Needs you / Working / Unread / Done`, rows grouped by
  `Today / Yesterday / Earlier`, each row shows title (or "Untitled chat"), model·status tag, and
  time; "New chat" primary action; keyboard `↑/↓/Enter` moves/opens.
- Status bar: kernel health, running count, open approval count, `⌘K` hint.
- Unit tests: filter mapping from session metadata, grouping, empty states.

### 3. Chat surface: tabs, header, transcript

Files: `Tabs.tsx`, `Chat.tsx`, `ChatHeader.tsx`, `ToolCard.tsx`, `UsageMeter.tsx`,
`apps/desktop/test/chat-view.test.tsx`.

- Tabs for open sessions with close buttons; active tab owns the main area; `⌘W` closes a tab.
- Header: session title, model picker (enabled models, `session.setModel`), context meter
  (`used/window` with percent), turn timer (from `turn.started` to `turn.completed`), cost.
- Transcript: user/assistant blocks, reasoning collapsed by default, tool cards with status and
  collapsible output, approval card inline where it was requested.
- Reducer additions: `usage.inputTokens/outputTokens`, `files` from `file.changed`,
  `plan` from `plan.updated`, `turnStartedAt`, `lastCompletedTurn`. All replay-safe.
- Unit tests: reducer over a scripted event sequence (usage, tool output, plan, file changes).

### 4. Composer and interruption

Files: `Composer.tsx`, `Chat.tsx`, `styles.css`, `apps/desktop/test/composer.test.tsx`.

- States: idle / sending / queued / streaming / interrupted / error, with distinct affordances.
- `Enter` sends, `Shift+Enter` newline, `⌘Enter` sends even while streaming (queues), `Esc` interrupts
  when streaming, `⌘.` interrupts from anywhere in the shell.
- Queue is visible: a "Queued — runs after this turn" badge with cancel before the turn starts.
- Approval card is keyboard reachable: `1..9` choose option, `Esc` rejects when a reject option exists.

### 5. Inspector

Files: `Inspector.tsx`, `apps/desktop/test/inspector.test.tsx`.

- Sections: status + model + turn timer, usage (input/output/context/cost), pending approvals,
  changed files with `+/-` counts, plan items.
- Toggle with `⌘B`; on narrow widths it overlays the main pane instead of shrinking it.
- Empty state when no session is open.

### 6. Command palette and shortcuts

Files: `CommandPalette.tsx`, `commands.ts`, `useShortcuts.ts`, `apps/desktop/test/palette.test.tsx`.

- `⌘K` opens, fuzzy filter, `↑/↓/Enter`, `Esc` closes; commands run kernel RPCs or shell actions.
- Commands: new chat, close tab, switch theme, open Setup, focus composer, interrupt, toggle inspector,
  copy session id. Each declares its shortcut; the shortcut handler is generated from the registry.
- Test: filtering, disabled commands while busy, shortcut dispatch does not fire inside inputs except
  where declared.

### 7. Lifecycle e2e

- Real `omp` + mock provider: create chat from the list pane, send, see queued badge for a second
  prompt, interrupt the first turn, confirm the queued turn runs, restart the app and confirm the
  transcript replays with usage and tool card intact.
- Keep the existing chat/smoke specs passing (Setup flow and persistence).

### 8. Docs

Manual: both themes at 1280×800 and 960×640, keyboard-only pass (rail → list → tabs → composer →

## Risks

- **Session metadata query cost.** Two grouped queries per `session.list`; fine at M1 scale (sessions
  ≤ thousands). Revisit with an index on `events(session_id, seq)` if a profile shows otherwise.
- **Model switch mid-session.** ACP's `session/set_config_option` is only applied on the next prompt;
  the UI must show the pending model immediately but not claim the engine switched.
- **Tab state vs kernel truth.** Tabs restored from `localStorage` may reference deleted sessions;
  the shell must drop or grey them on the first `session.list`.
