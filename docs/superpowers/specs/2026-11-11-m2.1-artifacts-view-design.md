# M2.1 Artifacts View — Design

**Date:** 2026-11-11
**Status:** Approved design; implementation plan not written
**Milestone:** M2.1
**Depends on:** M1.5 (current `main`)

## 1. Intent

Add a read-only artifact preview to the main pane for Markdown, CSV/TSV, and PDF files produced in a workspace. It is called **Artifacts** in the UI; the tab kind is `preview`. It is not the pixel office (M2.2).

Success means: from the file tree, command palette, a chat file link, or the inspector, a user opens a Markdown, CSV, or PDF file without leaving the app; the content is rendered read-only; oversized or unreadable files produce a clear state; and no file bytes bypass the kernel.

## 2. Scope

### In scope

- A `preview` tab in the existing tab system.
- Kernel RPC `artifact.read` for text and binary files with caps.
- Markdown rendering with strict sanitization.
- CSV/TSV parsing and a read-only table.
- PDF rendering with pdf.js (worker, page navigation, zoom, fit-width).
- Loading/error/too-large states; tab restore.
- Entry points: file tree, ⌘K, chat file links, inspector.
- Unit, component, and E2E tests.

### Out of scope

- DOCX, XLSX, PPTX, images, video, audio.
- Editing, annotations, comments, or diff overlays inside the preview.
- Range requests, streaming reads, or files above 32 MiB.
- PDF text selection, search, print, or form filling.
- Syntax-highlighted code blocks in Markdown (plain `<pre>` is enough).
- Remote resources (images, fonts, iframes) inside previews.
- Office integration or shelling out to external viewers.

## 3. Kernel contract

New RPC:

```ts
artifactRead: "artifact.read"

export const ArtifactReadParams = z.object({
  workspaceId: z.string().min(1),
  path: z.string().min(1),
});

export const ArtifactReadResult = z.object({
  encoding: z.enum(["utf8", "base64"]),
  content: z.string(),
  size: z.number().int().nonnegative(),
  mtimeMs: z.number().int(),
  truncated: z.boolean(),
});
```

Rules:

- The path resolves through the same workspace guard as `fs.read`; absolute paths, `..`, and symlinks escaping the workspace are rejected with `RpcFault(invalidParams)` — that is what `relativePath`/`resolveInsideRoot` already return, and `fs.read` has always behaved this way.
- Files are classified by extension: `.md`, `.markdown`, `.csv`, `.tsv` are UTF-8 (2 MiB cap); `.pdf` is binary (32 MiB cap). Any other extension is rejected with `RpcFault(invalidParams, "Unsupported artifact type")`.
- Text above 2 MiB returns the first 2 MiB with `truncated: true`; PDF above 32 MiB is rejected with `RpcFault(conflict, "Artifact is larger than 32 MB")` — it is not silently cut.
- Binary encoding is base64. The RPC response is a normal JSON-RPC result; no new HTTP endpoint.
- Zod parsing happens before touching the filesystem.
- The result never includes the absolute filesystem path; the renderer only needs the workspace-relative path.

The kernel does not render or parse file content. No content from `artifact.read` enters the event log, so it is not redacted; it is user data displayed to the same user.

## 4. Renderer model

### 4.1 Tab

```ts
// apps/desktop/src/renderer/tabs.ts
| { id: string; kind: "preview"; path: string }
```

- `previewTab(path)` produces `id = "preview:" + path`.
- `openTab` focuses an existing preview tab for the same path.
- `preview` tabs are workspace-scoped like `editor`/`diff`; `scopeTabs` drops them when the workspace changes, and they are not pruned by session existence.
- The stored tab version becomes `noir.tabs.v3`; `loadTabs` accepts v2 and v3.

### 4.2 Components

```
apps/desktop/src/renderer/preview/ArtifactPreview.tsx   loads, classifies, renders states
apps/desktop/src/renderer/preview/MarkdownArtifact.tsx  react-markdown pipeline
apps/desktop/src/renderer/preview/CsvArtifact.tsx       table + summary
apps/desktop/src/renderer/preview/PdfArtifact.tsx       pdf.js canvas + toolbar
apps/desktop/src/renderer/preview/csv.ts                parser + delimiter/header inference
apps/desktop/src/renderer/preview/kind.ts               extension → "markdown" | "csv" | "pdf"
```

`ArtifactPreview` receives `{ workspaceId, path, request }` and:

- calls `artifact.read` on mount and on reload;
- aborts nothing at the RPC layer (JSON-RPC has no cancellation), but ignores a result whose tab closed (`AbortController`-style generation counter);
- renders `loading`, `ready`, or `error` with the kernel message, plus a Reload button. There is no separate `too-large` state: the kernel rejects a >32 MiB PDF with `conflict("Artifact is larger than 32 MB")`, so the error state carries it;
- shows `truncated: true` as "Showing the first 2 MB".

### 4.3 Markdown

- `react-markdown` with `remark-gfm` and `rehype-sanitize`.
- Raw HTML is disabled (`skipHtml` and no `rehype-raw`).
- Sanitize schema allows headings, lists, tables, code, blockquote, links, emphasis, and `del`; all `on*` attributes are dropped and `href` protocols are limited to `http`, `https`, and `mailto`.
- Images are **not** loaded in M2.1: `img` renders as its alt text (or its `src`) in a `<span class="artifact-image-ref">`. The sandbox can only reach `img-src 'self' data:`, so even an `https:` `src` would be blocked by CSP.
- Links: `http(s)` opens through the OS browser via the preload bridge; `mailto` opens the OS handler; relative/absolute workspace links focus or open the matching editor/preview tab; `javascript:` is stripped.
- Code blocks render as `<pre><code>`; no highlighter.
- The renderer sets `className="artifact-markdown"` for styling.

### 4.4 CSV/TSV

Parser (`csv.ts`), no dependency:

- RFC 4180 quotes, `""` escapes, embedded delimiters/newlines, CRLF, and a UTF-8 BOM.
- Delimiter inferred from the header line outside quotes among `, ; \t |`; default `,`.
- A header row is used when all cells in the first row are non-empty and at least one is non-numeric; otherwise columns are `Column 1..N`.
- Limits: 5,000 rows, 100 columns, 500 characters per cell. Parsing stops at the limits and reports `{ headers, rows, truncated, delimiter }`; row and column totals are only known when the file was small enough to count.
- The table is read-only, virtualized by simple windowing (render rows within ±50 of the scroll position), and shows "Showing N of M rows" when limited.
- Empty files show an empty state, not an error.

### 4.5 PDF

- `pdfjs-dist` with the worker loaded through a Vite `?url` import (`import("pdfjs-dist/build/pdf.worker.min.mjs?url")`), matching the Monaco worker approach; the asset is hashed into `dist/renderer/assets` and packed into `app.asar`. A runtime `new URL("pdfjs-dist/…", import.meta.url)` does not resolve a bare package path and must not be used.
- Decode base64 to `Uint8Array`, call `getDocument({ data })`, render the current page to a canvas at `devicePixelRatio` scale.
- Toolbar: previous/next, page `N / M`, zoom out/in, fit width. Fit width recomputes on container resize (ResizeObserver, debounced).
- Render only the current page in M2.1; a page cache of 2 rendered pages is allowed. Cancel an in-flight render when the page/zoom changes.
- Password-protected or malformed PDFs show an error state with the pdf.js message (no stack).
- Worker/CSP: `worker-src 'self' blob:;` must be allowed in the renderer CSP; no `eval` is required by pdf.js. If a build needs `wasm-unsafe-eval`, that is documented and tested before merge.

## 5. Entry points

- **File tree:** every previewable row gets a "Preview" action for `.md/.markdown/.csv/.tsv/.pdf`; a single click (and Enter/Space) keeps opening the editor, except `.pdf`, which opens the preview because Monaco cannot render it.
- **Command palette:** "Preview file…" lists all workspace files with supported extensions via `fs.files`; selecting opens the tab.
- **Chat:** `file_ref` and `diff_ref` blocks are surfaced by the reducer as file blocks and get a "Preview" action when the referenced path has a supported extension. `diff_ref` previews the working-tree file, not the blob.
- **Inspector:** changed-file rows get "Preview" beside "Show diff" when supported.
- Missing/deleted file: kernel `notFound` produces "File not found" with a Reload action.

## 6. Security

- No `file://` URLs, custom protocols, or direct renderer filesystem access.
- All bytes come from the authenticated kernel socket.
- Markdown sanitization is the XSS boundary; tests assert `<script>`, `onerror`, `javascript:` hrefs, `data:` images, and raw HTML are removed.
- `dangerouslySetInnerHTML` is not used anywhere in the preview path.
- PDFs are untrusted input parsed by pdf.js inside the sandboxed renderer; the 32 MiB cap bounds memory. No PDF JavaScript execution is enabled.
- The renderer has no CSP today; M2.1 adds a `<meta http-equiv="Content-Security-Policy">` to `apps/desktop/src/renderer/index.html`: `default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; worker-src 'self' blob:; connect-src 'self' ws://127.0.0.1:*` (Monaco and Phaser inject styles, so `unsafe-inline` stays; the kernel socket is `ws://127.0.0.1:<port>`). The Vite dev server needs `ws://localhost:*` added to `connect-src`; that variant is applied only when `import.meta.env.DEV` and asserted by the existing dev/editor E2E run. pdf.js needs no `eval` for its worker build.
- The preload gains `noir.openExternal(url)` backed by an Electron main IPC handler (`shell:openExternal`) that accepts only `http:`, `https:`, and `mailto:` URLs and calls `shell.openExternal`. The renderer never calls Electron APIs directly.

## 7. Testing and acceptance

Unit:

- `kind.ts`: supported/unsupported extensions, case-insensitive.
- `csv.ts`: quoted commas, escaped quotes, embedded newlines, CRLF, BOM, `;`/tab/pipe inference, empty file, header detection, 5,000-row/100-column/cell caps, unterminated quote.
- `artifact.read`: text happy path, binary happy path, unsupported extension, outside-workspace path, text truncation, >32 MiB PDF rejection, zod rejection.

Component:

- Markdown: renders GFM tables/task lists; strips script/onerror/javascript:/data images; external link calls the preload bridge.
- CSV: header and no-header tables; truncation note.
- PDF: with pdf.js mocked, shows page count and calls render with the decoded bytes; error state for a rejected document.
- ArtifactPreview: loading → ready, error message, too-large state, reload.

E2E (Playwright Electron):

- Create fixtures in a temp workspace: `notes.md` with a table and a script tag, `data.csv` with quoted commas/newlines, and a small generated PDF.
- Open each from the file tree; assert Markdown table, CSV cells, PDF canvas and page count.
- Restart the app; the preview tabs restore and re-read.
- Open a >32 MiB PDF fixture (sparse/large temp file) and assert the refusal state.

Acceptance:

1. Markdown, CSV/TSV, and PDF open from all four entry points.
2. No preview content can execute scripts or navigate the renderer to a hostile URL.
3. Oversized/unreadable/unsupported files produce explicit states, never a blank pane or crash.
4. `pnpm -r typecheck`, `pnpm -r test`, and desktop E2E pass; the packaged installer still starts and the new chunk loads inside `app.asar`.

## 8. Risks

| Risk | Mitigation |
|---|---|
| pdf.js worker fails in packaged asar/CSP | E2E against the packaged app or a `file://` build; CSP test; worker URL check |
| Markdown XSS | Sanitizer tests with hostile fixtures; no raw HTML |
| Large CSV memory | Row/column/cell caps and windowed rendering |
| Tab persistence mismatch across workspaces | v3 migration test and `scopeTabs` tests |
| PDF memory on huge pages | 32 MiB cap; render one page at a time |

## 9. Non-goals repeated for clarity

No Office document formats, editing, annotations, image preview, remote images, or range streaming. Those require separate designs.
