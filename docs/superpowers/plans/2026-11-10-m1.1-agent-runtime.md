# M1.1 Agent Runtime Implementation Plan (Plan 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A configured provider and model drive a real `omp acp` agent session whose streaming output, tool calls, and permission requests are persisted as events and rendered live in the Electron window.

**Architecture:** `@noir/omp-profile` renders and atomically writes the OMP profile (`models.yml`, `config.yml`, skills later) under `~/.omp/profiles/noir/agent`. `@noir/engine-acp` owns the ACP stdio client and maps ACP updates to normalized engine events. The kernel's `EngineManager` owns turns, prompt queueing, approvals, and event persistence; the renderer consumes only replayed/streamed events over the existing WebSocket. No agent loop lives in the renderer or Electron main.

**Tech Stack:** Node 24, pnpm workspaces, TypeScript strict, zod, better-sqlite3, ws, `@napi-rs/keyring`, `yaml`, React 19, Vite, Electron, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-09-noirharness-design.md` (sections 4, 6, 7, 8.3, 9, 10, 13 M1.1–M1.2 overlap).

## Global Constraints

- Node `>= 24`, pnpm `>= 10`, TypeScript `strict` plus `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes`.
- Windows first-class: every path (profile dir, workspace, session dir) must survive spaces and non-ASCII characters; never build shell command strings.
- Events are append-only; `seq` stays gap-free and unique per session under concurrent engine streams.
- Secrets exist in the OS vault and kernel memory, and in the engine profile files (0600) because the engine requires them there. They must never appear in SQLite, logs, events, RPC results, or the renderer except the profile file itself.
- The engine process is a child of the kernel; the kernel must reap it on close, crash, and session close.
- Permission decisions fail closed: unknown option, missing approval, or transport failure rejects the tool call.
- All UI copy English; one commit per task (`feat|test|docs|chore:`); new deps only in the task that names them.

## Review Focus

1. **Secret materialization** — API keys reach only `~/.omp/profiles/noir/agent/models.yml` (0600, atomic); no key in events, logs, error text, RPC, or git.
2. **Engine process lifecycle** — partial JSON lines, backpressure, cancel/dispose, crash, double dispose, and kernel shutdown leave no orphan `omp` process.
3. **Prompt integrity** — concurrent prompts with the same `requestId` are idempotent; prompts sent while running are queued and delivered in order at the idle boundary.
4. **Fail-closed permissions** — no path auto-allows; approvals are session-scoped and resolved exactly once.
5. **Stream integrity** — every engine chunk maps to an event with ascending `seq`; replay equals live state; unknown payloads become `engine.raw`, never dropped.

- [ ] **Step 2: Write ADR-0004**

```markdown
# ADR-0004: OS credential vault over app-managed encryption

Status: accepted (2026-11-10)

Provider API keys live in the OS credential vault (`@napi-rs/keyring`, service `NoirHarness`, account = provider id). SQLite stores only the vault handle. Kernel memory holds a key only while materializing the engine profile or during a provider health check. The engine profile file necessarily contains the key for `omp`; it is written atomically with 0600 under `~/.omp/profiles/noir/agent/` and is excluded from events, logs, and the workspace.

Consequence: Linux requires libsecret/Secret Service; provider creation fails loudly without it.
```

- [ ] **Step 3: Write ADR-0005**

```markdown
# ADR-0005: ACP is the first engine contract

Status: accepted (2026-11-10)

The kernel talks to agents through a normalized `AgentEngine` interface. The first implementation is an ACP stdio client that launches `omp --profile noir --session-dir <workspace>/.noir/sessions acp`. ACP's update stream maps onto the existing event types; unmappable payloads become `engine.raw`. The native engine (M2) implements the same interface, and the kernel contract does not change when OMP's ACP surface is upgraded to `--mode rpc`.

Consequence: engine quirks stay in `@noir/engine-acp`; the kernel and renderer never parse ACP.
```

- [ ] **Step 2: ModelService**

```ts
import type Database from "better-sqlite3";
import { v7 as uuidv7 } from "uuid";
import { ErrorCodes, RpcFault, type ModelCreateParams, type ModelView } from "@noir/protocol";

export class ModelService {
  constructor(private readonly db: Database.Database) {}

  create(params: ModelCreateParams): ModelView {
    const provider = this.db.prepare("SELECT id FROM providers WHERE id = ?").get(params.providerId);
    if (!provider) throw new RpcFault(ErrorCodes.notFound, "Provider not found");
    const exists = this.db.prepare("SELECT id FROM models WHERE provider_id = ? AND model_id = ?").get(params.providerId, params.modelId);
    if (exists) throw new RpcFault(ErrorCodes.conflict, "Model already exists for this provider");
    const row: ModelView = {
      id: uuidv7(),
      providerId: params.providerId,
      modelId: params.modelId,
      displayName: params.displayName ?? params.modelId,
      contextWindow: params.contextWindow,
      maxTokens: params.maxTokens ?? null,
      enabled: params.enabled,
      createdAt: Date.now(),
    };
    this.db.prepare(
      "INSERT INTO models (id, provider_id, model_id, display_name, context_window, max_tokens, enabled) VALUES (?,?,?,?,?,?,?)",
    ).run(row.id, row.providerId, row.modelId, row.displayName, row.contextWindow, row.maxTokens, row.enabled ? 1 : 0);
    return row;
  }

  list(providerId?: string): ModelView[] {
    const sql = `SELECT m.id, m.provider_id, m.model_id, m.display_name, m.context_window, m.max_tokens,
                        m.enabled, p.created_at
                 FROM models m JOIN providers p ON p.id = m.provider_id
                 ${providerId ? "WHERE m.provider_id = ?" : ""}
                 ORDER BY m.display_name`;
    const rows = (providerId ? this.db.prepare(sql).all(providerId) : this.db.prepare(sql).all()) as Array<Record<string, unknown>>;
    return rows.map((r) => ({
      id: r.id as string,
      providerId: r.provider_id as string,
      modelId: r.model_id as string,
      displayName: r.display_name as string,
      contextWindow: r.context_window as number,
      maxTokens: (r.max_tokens as number | null) ?? null,
      enabled: (r.enabled as number) === 1,
      createdAt: r.created_at as number,
    }));
  }

  remove(id: string): void {
    const result = this.db.prepare("DELETE FROM models WHERE id = ?").run(id);
    if (result.changes === 0) throw new RpcFault(ErrorCodes.notFound, "Model not found");
  }
}
```

Note: the `models` table has no `created_at`; the view reuses the provider's `created_at` so the wire view stays complete. Do not add another migration column.

```ts
export interface JsonRpcTransport {
  write(line: string): void;
  onLine(handler: (line: string) => void): void;
  onClose(handler: (error?: Error) => void): void;
  dispose(): void;
}

export class JsonRpcClient {
  constructor(transport: JsonRpcTransport, opts?: { requestTimeoutMs?: number });
  request<T = unknown>(method: string, params?: unknown, timeoutMs?: number): Promise<T>;
  notify(method: string, params?: unknown): void;
  /** Agent -> client requests; handler returns the result or throws. */
  onRequest(handler: (method: string, params: unknown) => Promise<unknown> | unknown): void;
  onNotification(handler: (method: string, params: unknown) => void): void;
  onClose(handler: (error?: Error) => void): void;

}
```

Rules: buffer stdout until `\n`, handle `\r\n`, parse each complete line, ignore blank lines, never parse stderr; outbound ids start at 1; inbound request ids are echoed verbatim; a request timeout rejects and removes the pending entry; `dispose` rejects all pending requests. `initialize` sends `{protocolVersion:1, clientCapabilities:{fs:{readTextFile:true,writeTextFile:true},terminal:true}}`. `newSession` sends `{cwd, mcpServers:[]}` and throws a descriptive `Error` if `configOptions` has no `category:"model"` entry (profile has no usable model). `prompt` sends the text blocks, resets a watchdog on every update, and on timeout sends `session/cancel` and resolves `{stopReason:"cancelled", timedOut:true}` once the prompt settles (bounded by a 5 s grace, then reject). - [ ] **Step 4: Terminal and fs handlers**

- [ ] **Step 2: Engine manager**

```ts
export class EngineManager {
  constructor(private readonly deps: {
    db: Database.Database; events: EventStore; sessions: SessionService; models: ModelService;
    providers: ProviderService; dataDir: string; home: string;
    ompCommand?: string; turnTimeoutMs?: number;

  prompt(params: SessionPromptParams): Promise<SessionPromptResult>;
  interrupt(sessionId: string): Promise<{ interrupted: boolean }>;
  respond(approvalId: string, decision: PermissionDecision): Promise<void>;

  shutdown(): Promise<void>;
}
```

Per-session state: engine client + session (created lazily on the first prompt after `syncProfile`), workspace root, current turn, in-memory queue, pending approval resolvers, last usage (size/used/cost), open assistant message ids.

Engine launch is configurable for tests without a fake binary: `NOIR_OMP_COMMAND` (default `omp`), `NOIR_OMP_ARGS_JSON` (default `[]`, parsed as a string array placed before the generated flags), `NOIR_PROFILE_HOME` (default `os.homedir()`), `NOIR_TURN_TIMEOUT_MS` (default `120000`). The kernel always appends `--profile noir --session-dir <workspace>/.noir/sessions --model <selector> acp` and spawns with `cwd` = workspace root. The fake ACP server ignores unknown argv.

`prompt`:
1. Load the session (status, workspace path, model). Reject `closed` sessions with `conflict`.
2. Idempotency: `SELECT id, status FROM turns WHERE session_id = ? AND client_request_id = ?`. If found, return `{turnId, queued: status === "queued"}` without emitting anything.
3. Insert a `turns` row (`idx` = count + 1, `client_request_id`, `status` = `queued` or `running`).
4. If the session is `idle`/`starting` (after ensuring the engine), deliver immediately: set status `running`, emit `turn.started`, call engine `prompt`, set the row `running`/`started_at`.
5. If `running`/`waiting`, leave the row `queued` and return `{turnId, queued:true}`; on turn end, drain in insertion order.

Delivering a turn:
- Resolve the model selector `"<provider name>/<modelId>"` from the session's model and pass it as `--model` at spawn; if the session's model changed while running, call `setConfigOption("model", selector)` before the next prompt.
- On each engine update, append an event (`agentId`, `turnId`, provenance `{engine:"acp", engineName:"omp", adapterVersion:"<package version>"}`):

| Engine update | Event |
|---|---|
| `message` (reasoning=false) | `message.delta {messageId, role:"assistant", block:{type:"text",text}}` |
| `message` (reasoning=true) | same with `block:{type:"reasoning",text}` |
| `tool.started` | `tool.started {toolCallId,title}`; if `toolKind === "execute"` also `command.started {commandId: toolCallId, command: rawInput.command ?? title}` |
| `tool.updated` (completed/failed) | `tool.completed {toolCallId,status}` or `tool.failed {toolCallId,message}` (message from `text` or status) |
| `tool.updated` (in progress) | no event (avoid churn) |
| `usage` | remember; emit nothing yet |
| `plan` | `plan.updated {items: entries.map(e => ({text: e.content, status: mapStatus(e.status)}))}` |
| `title` | `session.updated {title}` and update the row |
| `raw` | `engine.raw {engine:"omp", payload: update}` |

- On turn end: emit `message.completed {messageId, status}` for every open assistant message (`status: "done"`, or `"interrupted"` when the stop reason is `cancelled`), then `usage.updated` when the update or result produced numbers (`inputTokens`/`outputTokens` from the result, `contextUsed`/`contextWindow`/`costUsd` from the last usage update, defaults 0), then `turn.completed {turnId, status:"completed"|"interrupted", stopReason}`, set the turns row `done`/`interrupted`/`failed` with `ended_at`, set session `idle`, drain the queue.
- If the engine throws or the process exits mid-turn: emit `turn.failed {turnId,message}`, set the session `error`, fail the queued turns in the queue (emit `turn.failed` for each), clear the queue.

`respond`: look up the approval; `conflict` when already decided; resolve the engine permission promise; update `approvals` (`decision`, `decided_at`); emit `permission.resolved`; set the session `running` when it was `waiting`; then delivery continues through the engine.

`interrupt`: if a turn is running, call `engine.cancel()` and let the turn settle as interrupted; return `{interrupted:false}` when idle; drop queued turns by emitting `turn.failed {message:"interrupted"}` for each and deleting their rows.

`closeSession`: cancel, close the ACP session, dispose the client, close the session row/event, clear state. `shutdown` does this for every session (called from `startKernel`'s `close()` before the DB closes).

- [ ] **Step 3: Event broadcast stays global**

The RPC server broadcasts every appended event (`{method:"event", params:{event}}`) to all authenticated sockets; the renderer filters by `sessionId`. `session.subscribe` keeps replaying from `sinceSeq` and its result carries `{events, lastSeq}`. Registering per-session listeners is intentionally deferred until multi-window support.

Register `session.prompt`, `session.interrupt`, `session.close`, `approval.respond`. `session.create` must call `syncProfile`-dependent validation but must not spawn an engine. Wire `EngineManager.shutdown()` into the kernel `close()` path before `db.close()`.
