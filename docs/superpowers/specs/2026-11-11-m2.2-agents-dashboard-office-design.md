# M2.2 Agents Dashboard and Pixel Office — Design

**Date:** 2026-11-11
**Status:** Approved design; implementation plan not written
**Milestone:** M2.2
**Depends on:** M1.5; optionally M2.0 for `tool.started.kind` (if M2.0 lands first, ACP must emit the same field)

## 1. Intent

Turn the existing `Agents` concept into a first-class surface: persistent agent profiles, a live roster, per-agent model/permission configuration with the enabled skills available to every agent, and a pixel-art office that visualizes what each agent is doing. The office is the dashboard's main pane; the roster and inspector remain the accessible, complete way to operate it.

Success means: create an agent, start a session from it, watch its character move and animate from real kernel events, see a speech bubble when it needs approval, click the character to select and open its session — with no second agent runtime and no fork of pixel-agents or agent-town.

## 2. Current state (ground truth)

- `agents` already exists: `id, name, role, engine_id, model_ref, skill_ids, permission_policy, parent_id`.
- `SessionService.create` inserts a fresh `Agent` row for every session and hardcodes `engine = "acp"`.
- `sessions.config_snapshot_json` exists but is written empty.
- `EngineManager.handlePermission` always emits `permission.requested`; no policy is enforced.
- The renderer has no Agents view; the rail is `Chats | Skills | Setup`.
- `session.list` already exposes status, `pendingApproval`, `lastEventAt`, and `engine`.
- Every event is broadcast to every connected client, so the office can observe all sessions without a new stream.

## 3. Scope

### In scope

- Agent profile CRUD + archive; global profiles; optional default workspace.
- `session.create` from an agent, with a config snapshot.
- Permission policy enforcement (`ask | allow | reject` per category) and an auditable `permission.auto` event.
- Kernel-derived roster status and `agent.roster` RPC.
- Agents rail: roster, office main pane, inspector config.
- Phaser 3 pixel office: fixed map, CC0 assets, deterministic desks, movement from tool kind, approval/error bubbles.
- Roster/list fallback and keyboard operation.
- Unit, component, kernel, and E2E tests.

### Out of scope

- Per-agent skill filtering (the engine profile is kernel-wide; see §6).
- In-world task assignment, office layout editor, character editor, furniture interactions.
- Multiplayer, shared world, music, mobile layout.
- Forking or embedding pixel-agents or agent-town.
- Hard deletion of agents with sessions.
- Agent hierarchy (`parent_id` remains reserved/unused).
- Remote asset loading.

## 4. Data model

Migration 6:

```sql
ALTER TABLE agents ADD COLUMN default_workspace_id TEXT REFERENCES workspaces(id) ON DELETE SET NULL;
ALTER TABLE agents ADD COLUMN archived_at INTEGER;
ALTER TABLE agents ADD COLUMN created_at INTEGER NOT NULL DEFAULT 0;
CREATE INDEX idx_agents_archived ON agents(archived_at);
```

No other schema change. `skill_ids` and `permission_policy` already exist. `parent_id` stays reserved.

Profile fields:

| Field | Type | Rules |
|---|---|---|
| `name` | string | 1–60 chars, unique among non-archived agents (case-insensitive) |
| `role` | string | 1–40 chars, free text, default `"Coder"` |
| `engine_id` | `"acp" \| "native"` | default `"acp"`; display/session default only |
| `model_ref` | model id or null | null means the kernel default model at session start |
| `skill_ids` | `string[]` | reserved for M3; not edited, not copied into sessions, and not used for filtering |
| `permission_policy` | object | `{ shell?: "ask"\|"allow"\|"reject", delete?: …, rename?: …, "write-outside-workspace"?: …, network?: … }`; missing = `ask` |
| `default_workspace_id` | workspace id or null | preselected when starting a session |
| `archived_at` | timestamp or null | archived profiles are hidden from start pickers and the default roster filter |

## 5. RPC surface

```ts
agentList: "agent.list"        // { includeArchived?: boolean } → { agents: AgentView[] }
agentCreate: "agent.create"    // AgentCreateParams → AgentView
agentUpdate: "agent.update"    // { id, name?, role?, engineId?, modelRef?, permissionPolicy?, defaultWorkspaceId? } → AgentView
agentArchive: "agent.archive"  // { id, archived: boolean } → { ok: true }
agentRoster: "agent.roster"    // {} → { agents: AgentRosterEntry[], generatedAt: number }

export const AgentView = z.object({
  id: z.string(),
  name: z.string(),
  role: z.string(),
  engineId: z.enum(["acp", "native"]),
  modelRef: z.string().nullable(),
  permissionPolicy: z.record(PermissionCategory, z.enum(["ask", "allow", "reject"])).partial(),
  defaultWorkspaceId: z.string().nullable(),
  archivedAt: z.number().int().nullable(),
  createdAt: z.number().int(),
});

export const AgentRosterEntry = z.object({
  agentId: z.string(),
  name: z.string(),
  role: z.string(),
  status: z.enum(["idle", "working", "needs_you", "error"]),
  activeSessionId: z.string().nullable(),
  activeSessionStatus: SessionStatus.nullable(),
  activeToolKind: z.enum(["read", "write", "shell", "search", "skill", "other"]).nullable(),
  sessionCount: z.number().int().nonnegative(),
  lastActivityAt: z.number().int(),
  usage: z.object({ used: z.number().int(), size: z.number().int() }).nullable(),
});
```

Protocol additions: `PermissionCategory = z.enum(["shell","delete","rename","write-outside-workspace","network"])` exported from `@noir/protocol` (reused by the event schema), and `"permission.auto"` added to `EventType` and `PayloadSchemas`.

- `agent.list` is sorted by `name`; archived are excluded unless requested.
- `agent.create` validates the name uniqueness, the model (if set) is enabled, and the engine/model compatibility used by `session.create`.
- `agent.update` applies only to future sessions; it never mutates a running session.
- `agent.roster` is the office's snapshot. The renderer refreshes it on broadcast `session.*`, `turn.*`, `tool.*`, `permission.*`, and `usage.updated` events, coalesced to at most one call per 250 ms. There is no separate `agent.subscribe` RPC: every event is already broadcast to every client.
- `agent.archive` is idempotent. Sessions and history keep their `agent_id`.

### Session creation

`SessionCreateParams` becomes:

```ts
z.object({
  workspaceId: z.string().min(1),
  modelId: z.string().optional(),
  agentId: z.string().optional(),
})
```

`SessionService.create`:

1. Loads the agent when `agentId` is present; rejects archived agents with `conflict`.
2. Resolves model: explicit `modelId` > `agent.model_ref` > kernel default. Rejects a disabled/missing model.
3. Resolves engine: `models.engine` when a model is chosen, otherwise `agent.engine_id`; a native engine requires an `openai-completions` provider.
4. Inserts the session with that engine and `config_snapshot_json = { agentId, engine, modelId, permissionPolicy }`.
5. When `agentId` is absent, keeps the current behavior: a fresh `Agent` row named `"Agent"` with the kernel default engine. This preserves M1 callers and tests.

The snapshot is the session's authority for policy and display. `session.list`/`session.view` may expose `agentId` (already present).

## 6. Skills: available, not per-agent

The engine profile is kernel-wide (`<dataDir>/engine`) and the materialized skill set (`.noir/skills-engine`) is per workspace. Every enabled skill is available to every session regardless of which agent started it.

- Agents load skills on demand through the engine's skill tools (`skill.list` / `skill.read` for native; the equivalent ACP read path), based on the task in front of them. The agent decides what it needs at the start of the work; the profile does not restrict it.
- The config inspector shows the enabled skills as a read-only "Available skills" list with scope and description. There is no selection control and no per-agent filter.
- `agents.skill_ids` stays in the schema as reserved for M3's registry and is not written by M2.2 RPCs.
- The session snapshot omits skills entirely; changing the agent profile cannot alter which skills exist.

## 7. Permission policy

Policy is enforced in `EngineManager.handlePermission` before any approval is emitted:

```
allowed = policy[category] ?? "ask"
if category == "write-outside-workspace" and path is outside workspace -> "ask" (override)
allow  -> return "allow_once" immediately; emit permission.auto { decision: "allow_once" }
reject -> return "reject"; emit permission.auto { decision: "reject" }
ask    -> current behavior: permission.requested + approval row + waiting status
```

New event:

```ts
"permission.auto": z.object({
  category: PermissionCategory,
  title: z.string(),
  decision: z.enum(["allow_once", "reject"]),
})
```

- `permission.auto` is appended with the agent/session/turn provenance, redacted like every event, and projected into no approval row.
- ACP tool calls and native tools both pass through this function; `category` comes from the existing `permissionCategory(toolKind)` mapping.
- Auto decisions are included in replay and audit; the UI may show them as a muted system line, but they never require a decision.
- The policy is read from the session snapshot, not the live profile, so editing a profile cannot change a running session.

## 8. UI

Rail gains `Agents` between `Chats` and `Skills`. Regions: `Agents` (list), `Office` (main), `Agent config` (inspector).

Roster row: name, role, model display name, default workspace name, status dot, active session count, last activity. Actions: select, Start, Archive/Unarchive. Archived agents appear under a filter.

Config inspector:

- Name, role, engine (acp/native) with a one-line capability hint, default model, default workspace, available skills (read-only list), permission matrix (five categories × Ask/Allow/Reject), Archive.
- Start panel: workspace (default preselected), model (default preselected), Start. On success, open the new chat tab.
- Errors from RPCs are shown inline, never as a blank form.

Office main pane:

- Header: selected agent name, status, model, context bar, active session count.
- Canvas fills the pane; roster remains visible for keyboard users.
- Selecting a character selects the roster row; selecting a row highlights the character.
- "Open chat" opens the active session tab; "Configure" focuses the inspector.
- Empty state: "No agents yet" with a Create agent action.

## 9. Pixel office

### 9.1 Technology and isolation

- Phaser 3, lazy-loaded with `import()` so the office chunk is not in the initial renderer bundle.
- One React component `AgentOffice` owns the `Phaser.Game`; it destroys the game on unmount and on workspace/view change.
- Phaser never calls the kernel. It receives `AgentOfficeState[]` and emits only selection events.
- If WebGL is unavailable, Phaser falls back to Canvas; if Phaser fails to construct, the pane shows the roster with "Office unavailable" and keeps working.

### 9.2 Map and assets

- Fixed 24×16 top-down office defined in `office-map.json` (tile layers: floor, wall, furniture; collision grid; zones).
- Curated CC0 tileset/character pack committed under `apps/desktop/src/renderer/office/assets/` with a `LICENSE.md`; `assets/manifest.json` maps names to frames. No Metro City or agent-town art.
- Deterministic desk assignment: `deskIndex = hash(agentId) % desks.length`; collisions resolve to the next free desk in id order, stable across restarts.
- Furniture zones: desk, shelf (`read`/`search`/`skill`), terminal rack (`shell`), lounge (idle wander).
- Camera fits the map to the pane, integer scaling, `image-rendering: pixelated`.

### 9.3 State mapping (pure)

```ts
type OfficeAction = "idle" | "working" | "reading" | "shell" | "blocked" | "error";

interface AgentOfficeState {
  agentId: string;
  name: string;
  status: "idle" | "working" | "needs_you" | "error";
  action: OfficeAction;
  desk: { x: number; y: number };
}
```

Mapping (`office/mapper.ts`, unit-tested, no Phaser import):

- `needs_you` → `blocked`, destination desk, speech bubble.
- `error` → `error`, destination desk, error marker.
- `working` + tool kind `read|search|skill` → `reading`, destination shelf.
- `working` + `shell` → `shell`, destination rack.
- `working` + `write|other|null` → `working`, destination desk.
- `idle` → `idle`, destination desk; after 8 s idle it wanders between lounge points, returning before the next action.

Movement rules:

- 4-direction A* on the collision grid; no diagonals; one tile per 120 ms.
- On action change: walk to the new destination, then play that action animation; while walking play `walk`.
- Missing destination (blocked) keeps the agent at its desk.
- `prefers-reduced-motion`: no movement or wander; render seated state with a status icon.

### 9.4 HUD and accessibility

- Speech bubble for `needs_you` with the approval title, truncated at 80 chars.
- Status icon (working/blocked/error) above the character.
- Canvas is `aria-hidden`; the roster is the accessible equivalent. Focus on a roster row highlights the character; Enter opens the chat; `C` focuses config.
- No music, no sounds in M2.2.
- A visible `List view` toggle hides the canvas and keeps the roster/config (session state, no persistence needed; defaults to office).

### 9.5 Performance

- Roster snapshots are coalesced (250 ms) and diffed by agent id + action; unchanged characters get no tween restart.
- At most 32 characters render; additional agents do not appear in the office and the header says "N more agents in the roster".
- The Phaser game runs at 30 FPS; `visibilitychange` pauses the loop when the window is hidden.

## 10. Testing and acceptance

Kernel/unit:

- Agent CRUD validation: duplicate name, invalid model, archived agent cannot start, archive idempotent.
- Session snapshot immutability: update profile after create; session policy and model do not change.
- Engine resolution: model engine wins; native rejected without an OpenAI-compatible provider; no-agent path still works.
- Policy matrix: `ask` unchanged, `allow` emits `permission.auto` and never `permission.requested`, `reject` fails closed, outside-workspace write forces ask.
- `permission.auto` replay and redaction.
- Roster precedence (`needs_you` > `working` > `error` > `idle`), active session selection, last activity.
- Mapper: every status × tool kind; desk hash stability and collision resolution; pathfinder on the fixture grid.

Component:

- Roster renders status/time; config form validates and saves; Start opens a chat tab; archive removes from default list.
- Office mount/dispose does not leak a Phaser game (mock Phaser); selection parity roster ↔ office; List view toggle.

E2E (Playwright Electron, fake provider):

- Create an agent bound to a model; start a session; prompt `slow`; office shows one character in `working`.
- Trigger a tool that needs approval; bubble appears; roster shows Needs you; approve; bubble clears.
- Restart the app; agent and session persist; character returns to desk.
- List view toggle; keyboard selection opens the chat.
- Two agents with sessions render two characters; clicking one selects its roster row.

Acceptance:

1. Every approved dashboard action exists as an RPC first; the UI uses only those RPCs.
2. Policy enforcement is observable in events and replay: `allow`/`reject` never create an approval row.
3. No second runtime: the office consumes `agent.roster` and broadcast events only.
4. Roster + list view provide complete operation without the canvas.
5. `pnpm -r typecheck`, `pnpm -r test`, desktop E2E, and the packaged installer pass; the office chunk loads from `app.asar`.

## 11. Risks

| Risk | Mitigation |
|---|---|
| Phaser/WebGL context loss in Electron | Canvas fallback, List view, destroy/recreate on visibility loss |
| Office chunk bloats startup | Lazy import; Vite manual chunk; measured bundle budget in the plan |
| Event-rate thrash | 250 ms coalescing, action diffing, 30 FPS, max 32 characters |
| Art licensing | Curated CC0 pack, committed license, no third-party packs |
| Accessibility regression | Roster is complete; canvas aria-hidden; keyboard tests |
| Policy bypass | Read from session snapshot; outside-workspace override; matrix tests |
| Per-agent skills look configurable but are not | No selection control; read-only available-skills list; `skill_ids` reserved |

## 12. Explicit non-adoption

Neither upstream project is embedded or forked. Reused patterns (pathfinding, worker/entity split, sprite manifest) are reimplemented in Noir code under their MIT terms; no upstream runtime, hook protocol, OpenClaw gateway, or art is shipped. This keeps one event source and one security boundary.
