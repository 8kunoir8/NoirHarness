# M7.0 — Shell surfaces: context menus, source control, help, update notice

Status: design. Approved in conversation 2026-11-15; written here for review.

## 1. Intent

Four surfaces the app is missing, all of them about *orientation*: what can I do with this thing I am
pointing at, what have I changed, where do I find out how this works, and am I running an old build.

What a user does:

1. **Right-click** a chat row, a transcript message, a tab, a file, or a selection in the editor and
   gets the actions that already exist for that object, in the place the pointer is.
2. Opens **Source** (nav, the chat header's `+12 −3`, or the status bar's branch) to see staged and
   unstaged work, stage or unstage a file, and commit with a message.
3. Opens **Help** (nav or F1) to read the keyboard map this build actually implements, the running
   version and build id, and links out to the repo.
4. Sees a badge on **Help** and one toast when a newer release tag exists on the remote.

Success is: every one of those is reachable by mouse and by keyboard, every menu item maps to
behaviour that already existed or is defined here, and nothing in the update path can block a turn,
a start-up, or the UI.

## 2. Decisions

| Decision | Choice | Why |
|---|---|---|
| Menu implementation | Renderer-drawn, one component | The app draws its own chrome and theme; Playwright cannot assert a native `Menu.popup`, and 29 e2e specs are the proof standard here |
| Source-control scope | Stage, unstage, commit — local only | Push/pull need credentials and network failure states that deserve their own spec |
| Where Source and Help live | Nav views, full main area | The list column is 300 px with two modes already; a staging table needs the main width |
| Chat → Source link | Header diff stats and status-bar branch become buttons | Both already show exactly the data the page is about; no new affordance to learn |
| Update channel | `git ls-remote --tags` against the repo URL | The only channel that works today: private repo, no releases, and git already holds the user's credentials |
| Update policy owner | Kernel | One place decides cadence and "seen", so two windows cannot disagree and the renderer stays stateless |
| Version source | `app.getVersion()` → `NOIR_APP_VERSION` → `system.health.version` | The packaged app's version is Electron's, not any workspace file's |
| Release definition | A tag `v<version>` on the remote | The check compares against tags, so a release must be a tag; Help says so |

## 3. Context menus

### 3.1 Component

New `apps/desktop/src/renderer/ContextMenu.tsx`. A provider mounted once by `App`, a portal-rendered
menu, and a hook:

```ts
type MenuItem =
  | { kind: "separator" }
  | {
      kind: "item";
      id: string;
      label: string;
      /** Right-aligned, e.g. a shortcut. */
      hint?: string;
      /** Present means disabled, and the text is the reason shown as a title. */
      disabled?: string;
      danger?: boolean;
      run: () => void;
    };

interface MenuHandle {
  /** Coordinates are viewport client coordinates, as the pointer event reports them. */
  open(items: readonly MenuItem[], at: { x: number; y: number }): void;
}
```

Rules the implementation must hold:

- One menu exists at a time; opening a second replaces the first.
- Focus moves to the first enabled item on open and returns to the element that opened it on close.
- Keyboard: ArrowUp/ArrowDown move over enabled items, Home/End jump, Enter or Space runs the
  focused item, Escape closes. Tab closes.
- Closes on outside `pointerdown`, window `blur`, `resize`, and any scroll in the window.
- Measured after mount and clamped into the viewport; a menu near the right or bottom edge flips
  rather than overflowing.
- Escape is handled before any other Escape handler: a menu is the innermost surface, so it must not
  reach the rewind dialog behind it.
- Disabled items are focusable-by-arrow only when enabled; a menu with no enabled item still renders
  (it explains why everything is unavailable) and closes on Escape.
- Items are re-read only on open. A menu is a snapshot: state changes underneath do not re-render it.

Surfaces attach with `onContextMenu` and call `event.preventDefault()`. No row's primary click
behaviour changes.

### 3.2 Surfaces and items

| Surface | Items |
|---|---|
| Chat row (`SessionList`) | Rename · Copy title · Delete |
| Transcript message (`Chat`) | Copy text · Quote in composer · Fork from here · Rewind to before this prompt |
| Tab (`TabStrip`) | Close · Close others · Close to the right |
| File-tree entry (`FileTree`) | Open · Diff · Copy path · Reveal in Explorer |
| Editor selection (`MonacoEditor`) | Copy · Add to chat |

Notes:

- **Quote in composer** inserts a fenced block naming the source chat and turn, then focuses the
  composer without sending. **Add to chat** does the same for an editor selection, tagged with the
  file path and line range.
- **Fork from here** needs no kernel work: `sessions.fork(sessionId, upToSeq)` already takes a cut
  point, and a message already carries `seq` (`events.ts`, `ChatMessage.seq`).
- **Rewind** is disabled with reason `No checkpoint for this turn` when `checkpoints.byTurn` has no
  entry — the same condition that hides today's inline link.
- **Reveal in Explorer** is one new IPC channel, `shell:showItemInFolder`, beside the existing
  `shell:openExternal`; it validates the path is inside the active workspace before calling
  `shell.showItemInFolder`.
- The chat row's existing `✎`/`✕` buttons stay. The menu is an alternative, not a replacement, so the
  discoverable path is unchanged.

## 4. Source control

### 4.1 Kernel contract

`GitFileStatus` gains two nullable fields, and `GitStatusResult` gains divergence:

```ts
export const GitFileStatus = z.object({
  path: z.string(),
  /** The merged summary the inspector and chat header already show; unchanged semantics. */
  change: z.enum(["created", "modified", "deleted"]),
  add: z.number().int().nonnegative(),
  del: z.number().int().nonnegative(),
  /** Index (staged) side of the `XY` status pair, or null when the index matches HEAD. */
  index: z.enum(["created", "modified", "deleted"]).nullable(),
  /** Worktree (unstaged) side, or null when the worktree matches the index. */
  worktree: z.enum(["created", "modified", "deleted"]).nullable(),
});
export const GitStatusResult = z.object({
  isRepo: z.boolean(),
  branch: z.string().nullable(),
  /** Commits the branch has that its upstream does not, and the reverse; 0 when there is no upstream. */
  ahead: z.number().int().nonnegative(),
  behind: z.number().int().nonnegative(),
  files: z.array(GitFileStatus),
});
```

A file with both staged and unstaged work keeps **one** row carrying both sides, so a path never
appears twice in `files`. The Source view renders it in both groups while it is in both states.

New methods, all workspace-scoped and guarded by `resolveInsideRoot` per path:

```ts
gitStage: "git.stage"    // { workspaceId, paths: string[] } → GitStatusResult
gitUnstage: "git.unstage"// { workspaceId, paths: string[] } → GitStatusResult
gitCommit: "git.commit"  // { workspaceId, message } → { sha, summary, status: GitStatusResult }
```

Returning the fresh status saves the renderer a second round trip and removes the window in which the
page shows a stale index.

Behaviour:

- `git.stage` runs `git add -- <paths>`; a deleted path uses `git add -A -- <path>` so a deletion can
  be staged. `git.unstage` runs `git reset -q HEAD -- <paths>`, and on a repository with no commits
  (no HEAD) `git rm --cached -- <paths>`.
- `git.commit` passes the message through `-m` in an argv array (no shell), trimmed. It does **not**
  stage anything: what is not staged is not committed.
- **One mutating command per workspace at a time.** RPC handlers are concurrent, so `gitService`
  keeps a `Map<workspaceId, Promise<unknown>>` chain; reads (`git.status`, `git.diff`) do not queue.
- Mutating commands get a 30 s timeout (commit hooks run); reads keep 5 s.
- Refusals, each with its own message: empty or whitespace-only message (`invalidParams`), nothing
  staged (`conflict`), unknown or escaping path (`invalidParams`), not a repository (`conflict`), git
  missing (`internal`, the `NOIR_GIT_COMMAND` name in the text), hook failure (`internal` with git's
  stderr verbatim — a hook that rejects a commit has a reason the user needs to read).

### 4.2 View

New `apps/desktop/src/renderer/Source.tsx`, reached by nav, palette, the chat header's diff stats and
the status bar's branch.

- Header: branch, `ahead`/`behind` when non-zero, `Refresh`, and the workspace name when more than one
  workspace exists (the page can be opened from a chat whose workspace is not the selected one).
- Groups: **Staged** and **Unstaged**, each a list of paths with a checkbox. Checking stages or
  unstages that one path; the group header carries a "Stage all" / "Unstage all" action.
- A path click opens the existing `DiffView` tab. Staged files diff against the index; the existing
  `git.diff` diffs against HEAD, so the diff shown for a fully staged file is the same content — this
  is stated in the UI as `git.diff` semantics rather than papered over.
- Commit box: a textarea, `Commit` disabled with a visible reason (`Nothing staged to commit`,
  `Write a commit message`), inline error from the RPC, and a success line naming the short sha.
- Empty state: `No changes` when the repo is clean, `Not a git repository` with the path when
  `isRepo` is false.
- The page never blocks: a mutating call disables its own controls and shows a busy label, not a
  modal.

## 5. Help

New `apps/desktop/src/renderer/Help.tsx`, reached by nav, palette, and F1.

- **Running this build**: version from `system.health.version`, build id from the kernel banner's
  existing handshake, engine dir. A copy button for the whole line, for bug reports.
- **Keyboard**: a table generated from the same `Command[]` array the shortcut handler dispatches
  (`commands.ts`), so a documented shortcut cannot drift from the implemented one. Commands without a
  shortcut are omitted.
- **Links**: README, docs, repo, issue tracker — all through `shell:openExternal`, which already
  refuses anything but `http(s)` and `mailto`.
- **Updates**: current version, latest tag, last checked, and `Check now`. States: `Up to date`,
  `v0.2.0 is available`, `Could not check` with the reason (offline, no tags, git missing).

## 6. Update check

### 6.1 Channel

`git ls-remote --tags <url>` run from the data directory — a packaged app has no checkout, so this
cannot hang off a workspace. `<url>` is a constant in the kernel with an override, mirroring
`NOIR_GIT_COMMAND`:

- `NOIR_UPDATE_URL` — the remote to ask. Default: the project's repository URL.
- The command runs with `GIT_TERMINAL_PROMPT=0` and an 8 s timeout.

**The named risk:** against a private repository `ls-remote` can block on a credential prompt when the
helper has nothing cached. `GIT_TERMINAL_PROMPT=0` turns that into a fast failure, and every failure
path is silent — the app never announces a check it could not complete, and Help shows the reason.

### 6.2 Comparison

Tags are parsed as `v?<major>.<minor>.<patch>[-prerelease]`, compared numerically field by field. A
missing field counts as 0. A prerelease is lower than the release it precedes, and a tag that does not
parse is ignored rather than treated as newest. No new dependency; ~30 lines with its own unit test.

### 6.3 Policy

The kernel owns cadence and acknowledgement, in the existing `settings` table:

| Key | Meaning |
|---|---|
| `update.checkedAt` | Epoch ms of the last completed attempt |
| `update.latest` | Last tag observed, so a refresh needs no network |
| `update.dismissed` | Version the user dismissed the badge for |

```ts
updateCheck: "update.check"   // { force?: boolean } → UpdateState
updateDismiss: "update.dismiss" // { version } → { ok: true }
```

`update.check` answers from `update.latest` when the last attempt is under 24 h old and `force` is not
set; `force` always re-reads. `UpdateState` is:

```ts
{
  current: string;
  latest: string | null;
  status: "current" | "available" | "failed";
  /** Why the check failed, for Help; never shown as a toast. */
  reason?: string;
  checkedAt: number;
  /** True when the user dismissed this exact version. */
  dismissed: boolean;
  url: string;
}
```

### 6.4 What the user sees

- A badge (a dot) on the Help nav item while `status === "available"` and not `dismissed`.
- One toast per version, dismissible, with `What's new` (opens `url`) and `Dismiss` (calls
  `update.dismiss`). The toast is queued behind any approval notification, never shown over a dialog.
- The check runs after the window is up and the kernel is healthy, so it cannot delay start-up. A
  later failure changes nothing on screen.

### 6.5 Version and release step

All three manifests move from `0.0.0` to `0.1.0`, and `system.health.version` reports the running
app's version. A release is a commit that bumps the version plus a tag `v<version>` pushed to the
remote; without the tag the check correctly reports `Up to date`, which is why Help states the rule.

## 7. Protocol additions

| Method | Params | Result |
|---|---|---|
| `git.stage` | `{ workspaceId, paths[] }` | `GitStatusResult` |
| `git.unstage` | `{ workspaceId, paths[] }` | `GitStatusResult` |
| `git.commit` | `{ workspaceId, message }` | `{ sha, summary, status }` |
| `update.check` | `{ force? }` | `UpdateState` |
| `update.dismiss` | `{ version }` | `{ ok: true }` |

Changed results (additive only): `system.health` gains `version`, `git.status` gains `ahead`,
`behind`, and per-file `index`/`worktree`.

New IPC: `shell:showItemInFolder { path }`, validated inside the active workspace.

## 8. Testing

Unit:

- `ContextMenu`: opens at the pointer, clamps at both edges, arrow keys skip disabled items, Escape
  closes and is consumed, focus returns to the opener, outside pointerdown closes.
- `gitService`: stage, unstage, commit, and each refusal against a temporary repository; a file that is
  both staged and modified reports both sides in one row; a repository with no commits unstages via
  `rm --cached`; two concurrent commits serialize (the second sees the first).
- Version comparator: `v1.2.3` vs `1.2.4`, prerelease ordering, unparseable tags ignored, missing
  fields.
- `update.check` cadence: within 24 h answers from `update.latest` without invoking git; `force`
  invokes it; a failing git records `failed` and does not advance the answer.

e2e:

- Right-click a chat row → Rename opens the inline editor; Escape leaves the title unchanged.
- Right-click a message → Quote in composer puts the quoted block in the composer without sending.
- Right-click a file → Copy path puts the workspace-relative path on the clipboard.
- Source: edit a file, stage it, commit it, assert `git log -1 --pretty=%s` in the temp repo; then
  assert the page shows `No changes`.
- Help: shows the version the build reports and the shortcut table containing `Close tab`'s real key.
- Update: a temporary bare repository with a higher tag is set as `NOIR_UPDATE_URL`; the badge appears
  and the toast names the version. No test touches the network.

## 9. Out of scope

- Push, pull, fetch, branch switching, stash, merge/rebase, conflict resolution. `git.diff` keeps its
  current HEAD-relative semantics; a three-way index/preview diff is a later spec.
- A native OS menu, a tray menu item for updates, and an in-app updater that downloads and installs.
- Authenticating to the remote: the check uses whatever git already has.
- Any per-file history, blame, or commit log browser.

## 10. Risks

| Risk | Handling |
|---|---|
| `ls-remote` blocking on a credential prompt for a private repo | `GIT_TERMINAL_PROMPT=0` plus an 8 s timeout; failure is silent and explained only in Help |
| Concurrent commits interleaving | Per-workspace serialization of mutating commands, with a test that proves the second waits |
| A commit hook that hangs | 30 s timeout, then an error naming git rather than a spinner forever |
| Menu Escape stealing a dialog's Escape | Menu is registered as the innermost surface and consumes Escape while open |
| Chat header/status-bar buttons breaking existing e2e selectors | Both keep their current text and gain `role="button"`; existing assertions on `Diff stats` group stay valid |
| Deriving a version from `0.0.0` | Bumped to `0.1.0` in the three manifests as part of this work, and `system.health.version` is asserted in an e2e |
