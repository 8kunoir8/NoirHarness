# M2.0 Native Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an opt-in native engine that runs OpenAI-compatible chat-completions turns and built-in tools through the kernel, behind a shared engine contract.

**Architecture:** Extract the engine contract from `@noir/engine-acp` into `@noir/engine-core`; `EngineManager` selects ACP or native per `sessions.engine`. The native engine keeps history, streams SSE, assembles tool calls, executes kernel-backed tools, and returns the same `EngineUpdate`/approval shapes ACP already produces.

**Tech Stack:** TypeScript strict ESM, Node 24 `fetch`, zod, better-sqlite3 projection, Vitest, fake OpenAI SSE server.

**Spec:** `docs/superpowers/specs/2026-11-11-m2.0-native-engine-design.md`

## Global Constraints

- Node ≥ 24, pnpm ≥ 10, TypeScript strict with `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes`.
- ESM with `.js` extensions; Windows-first.
- Kernel is the only fs/git/DB authority; every RPC validates zod before touching state.
- No `python`/`sed` for edits; `edit`/`write` only.
- No new runtime dependency for the native engine; `fetch` and zod only.
- ACP behavior must not change; its existing tests are the regression gate.
- Never log API keys or unredacted provider responses.

## Review Focus

- What happens when the provider streams `tool_calls` split across chunks, including a fragment that is valid JSON only after concatenation.
- What happens when the user interrupts while a shell command is running, and whether the child tree dies.
- What happens when the kernel restarts mid-turn and the next prompt reconstructs history from events.
- What happens when an OpenAI-compatible server omits `usage` or returns a non-2xx JSON error containing the key.
- What happens when a tool argument fails zod validation: the turn must continue with a failed tool result, not abort.

```ts
import type { Engine, EngineSession } from "@noir/engine-core";
export * from "@noir/engine-core";

/**
 * One `AcpClient` (and so one child process) per engine instance, matching what `EngineManager`
 * does today: the session owns the client and reaps it on dispose, so no call site can leak the
 * child by forgetting the second half of a two-object teardown.
 */
export function createAcpEngine(opts: CreateAcpClientOptions): Engine {
  return {
    id: "acp",
    capabilities: {
      streaming: true, tools: true, diffs: true, approvals: true,
      subagents: true, steering: true, modelSelection: true,
    },
    async start(startOpts) {
      const client = await createAcpClient(opts);
      let session: AcpSession;
      try {
        session = await client.newSession(startOpts.cwd);
      } catch (error) {
        await client.dispose().catch(() => undefined);
        throw error;
      }
      const engineSession: EngineSession = {
        pid: client.pid,
        prompt: (content, handlers) => session.prompt(content, handlers),
        interrupt: () => session.cancel(),
        setModel: async (model) => session.setConfigOption("model", `${model.providerName}/${model.modelId}`),
        dispose: async () => {
          await session.close().catch(() => undefined);
          await client.dispose().catch(() => undefined);
        },
      };
      return engineSession;
    },
  };
}
```

`CreateAcpClientOptions` carries `command`, `args`, `cwd`, `env`, `turnTimeoutMs`; `EngineManager` builds the same args it builds today.

`parseSseChunks` buffers text, splits on `\n`, strips `\r`, ignores `:` lines, joins `data:` payloads with `\n`, parses JSON, and stops at `[DONE]`. It releases the buffer after each event.

`client.ts`:

```ts
export async function* streamChat(opts: {
  baseUrl: string; apiKey: string; body: unknown; signal: AbortSignal;
}): AsyncGenerator<unknown> {
  const res = await fetch(`${opts.baseUrl.replace(/\/+$/, "")}/chat/completions`, {
    method: "POST", redirect: "error", signal: opts.signal,
    headers: { "content-type": "application/json", authorization: `Bearer ${opts.apiKey}` },
    body: JSON.stringify(opts.body),
  });
  if (!res.ok) throw new ProviderHttpError(res.status, (await res.text()).slice(0, 8192));
  if (!res.body) throw new Error("Provider returned no body");
  yield* parseSseChunks(res.body);
}
```

`ProviderHttpError` keeps the body for the caller to redact.

`NativeEngine.start(opts)` returns a session with `#history` initialized from `opts.history`, `#controller`, `#busy`. `prompt`:

```ts
async prompt(content, handlers) {
  const text = content.map((b) => b.text).join("\n");
  this.#history.push({ role: "user", text });
  for (let round = 0; round < 24; round += 1) {
    const { text, toolCalls, finish, usage } = await this.#request(handlers, text);
    handlers.onUpdate({ kind: "message", messageId: this.#messageId, text, reasoning: false });
    if (toolCalls.length === 0) return { stopReason: finish ?? "stop", timedOut: false, usage };
    this.#history.push({ role: "assistant", text, toolCalls });
    for (const call of toolCalls) await this.#runTool(call, handlers);
  }
  throw new Error("Tool loop limit reached");
}
```

`#request` maps stream chunks to `{ text, toolCalls }`, concatenating `delta.tool_calls[i].function.arguments` by index and `id/name` when present. `usage` from `chunk.usage` when present.

Registry in kernel (`packages/kernel/src/engineRegistry.ts`):

```ts
export interface EngineRegistryDeps {
  db: Database.Database;
  providers: ProviderService;
  models: ModelService;
}

/** The enabled model a session's turns run against, completed with the provider endpoint and key. */
export function resolveModelFor(sessionId: string, deps: EngineRegistryDeps): EngineStartOptions["model"] & { baseUrl: string; apiKey: string } {
  const session = deps.db.prepare("SELECT model_id FROM sessions WHERE id = ?").get(sessionId) as { model_id: string | null } | undefined;
  if (session === undefined) throw new RpcFault(ErrorCodes.notFound, "Session not found");
  // Same precedence as the ACP selector: the session's model, else the kernel default.
  const modelId = session.model_id ?? deps.models.defaultModel()?.id;
  if (modelId === undefined) throw new RpcFault(ErrorCodes.conflict, "No model is configured for this session");
  const row = deps.db.prepare(
    `SELECT m.model_id, m.context_window, m.max_tokens, p.name AS provider_name, p.base_url, p.id AS provider_id
     FROM models m JOIN providers p ON p.id = m.provider_id
     WHERE m.id = ? AND m.enabled = 1 AND p.enabled = 1`,
  ).get(modelId) as Record<string, unknown> | undefined;
  if (row === undefined) throw new RpcFault(ErrorCodes.conflict, "The session model is disabled or missing");
  return {
    providerName: row.provider_name as string,
    modelId: row.model_id as string,
    contextWindow: row.context_window as number,
    maxTokens: (row.max_tokens as number | null) ?? null,
    baseUrl: row.base_url as string,
    apiKey: deps.providers.getKey(row.provider_id as string),
  };
}
```

The join is inner on an already-resolved `modelId`, so a session without a model falls back to the default model instead of failing the join. `getKey` throws `notFound("Provider key not found")` when the vault entry is gone, which fails the turn with a message that never contains the key.

`EngineManager.ensureEngine` reads `sessions.engine` and branches: `"acp"` keeps today's client construction (same command/args/env) but calls `createAcpEngine(opts).start({ ... })` so both engines return `EngineSession`; `"native"` calls `createNativeEngine().start({ sessionId, cwd: state.workspaceRoot, ...resolveModelFor(sessionId, deps), history: [], skills: [], turnTimeoutMs: this.turnTimeoutMs })`. Any other value throws `RpcFault(conflict, \`Unknown engine: ${id}\`)`, which `startTurn` already fails the turn on.

`SessionState` changes from `AcpClient | AcpSession` to the engine contract: `engine: Engine | undefined`, `engineSession: EngineSession | undefined`. Map the call sites: `engineSession.cancel()` → `interrupt()`, `engineSession.close()` → `dispose()`, `engine.dispose()` → `engineSession.dispose()` (the ACP adapter closes its client there). The model-change branch becomes:

```ts
const selector = this.selectorFor(state.sessionId);
if (state.selector !== selector) {
  const { baseUrl: _baseUrl, apiKey: _apiKey, ...model } = resolveModelFor(state.sessionId, this.registryDeps);
  await engineSession.setModel?.(model);
  state.selector = selector;
}
```

`enginePid()` returns `state.engineSession?.pid`. `EngineManager.disposeEngine` awaits `state.engineSession?.dispose()` and clears both fields and `selector`.

Use `node:fs/promises`, `node:path`, `node:child_process`. Every path is resolved with `resolve(root, input)` and checked with `relative(root, abs)`; reject `..` prefixes and symlink escapes (`realpath` of the parent). The native engine runs inside the kernel process, so it is the fs authority for its own tools; it must never be handed a root other than `state.workspaceRoot`.

`shell.exec` uses `spawn(command, { cwd, shell: true, windowsHide: true })`, collects stdout/stderr up to 64 KiB each, and on abort/timeout runs `taskkill /pid <pid> /T /F` on win32 or `process.kill(-pid, "SIGKILL")` on POSIX (spawn `detached` on POSIX).

Approval requests must carry the `kind` that `EngineManager.permissionCategory` already maps, so the approval card and M2.2's policy agree with ACP:

```ts
// fs.write / fs.replace / fs.delete / shell.exec → always ask in M2.0
await ctx.onPermission({
  sessionId,
  toolCall: { toolCallId, title: `Write ${rel}`, kind: "edit", rawInput: args },
  options: [
    { optionId: "allow", name: "Allow once", kind: "allow_once" },
    { optionId: "reject", name: "Reject", kind: "reject_once" },
  ],
});
```

- `fs.write`/`fs.replace` → `kind: "edit"` → category `write-outside-workspace` (matches ACP's edit path).
- `fs.delete` → `kind: "delete"` → category `delete`.
- `shell.exec` → `kind: "execute"` → category `shell`.

A decision other than `"allow_once"` short-circuits to the tool result `Permission denied by the user`. In the loop, a zod error becomes `Tool input invalid: <issue>`; both failures complete the call with `status: "failed"` while the turn continues.

- [ ] **Step 0: Persist the user prompt as an event**

Nothing writes user text to the event log today: `EngineManager.prompt` inserts a `turns` row and `Chat.tsx` appends the bubble locally (`appendUser`), so replay after a restart loses every user message and history reconstruction has nothing to rebuild from. Fix that in the kernel, before writing the history builder:

```ts
// prompt(), right after the turns row is inserted and only on the non-idempotent path:
const text = content.map((block) => block.text).join("\n");
this.emit(state, "message.delta", { messageId: params.requestId, role: "user", block: { type: "text", text } }, turnId);
this.emit(state, "message.completed", { messageId: params.requestId, status: "done" }, turnId);
```

`requestId` is already unique per send and the `turns(session_id, client_request_id)` unique index makes a retried prompt return early, so this appends exactly once. Emitting before `startTurn` keeps `turn.started` after the user message in `seq` order.

Renderer: `message.delta` with `role: "user"` and a `messageId` equal to the already-appended optimistic bubble must be a no-op, not an append — otherwise live sends show the prompt twice. Change the reducer branch so a `user` message that already exists is ignored, and `appendUserMessage` keeps using `requestId` as the id (it already does).

`reconstructHistory(events: AgentEvent[], limits: { contextWindow: number; maxTokens: number | null }): EngineHistoryMessage[]` groups events by `turnId`, joins that turn's user `message.delta` text blocks, reads assistant text from `message.delta` role `assistant`, pairs each `tool.started` with its `tool.output`/`tool.failed`, and drops the oldest whole turns until `chars / 4 <= contextWindow - (maxTokens ?? 0) - 2_000`.

Add `kind` to `PayloadSchemas["tool.started"]` and emit it from `handleUpdate`, using a kernel-local mapper (the office's action names are a renderer concern and must not leak into the event schema):

```ts
const TOOL_KINDS = ["read", "write", "shell", "search", "skill", "other"] as const;
type ToolKind = (typeof TOOL_KINDS)[number];

/** Native emits the office vocabulary directly; ACP emits its own (`execute`, `edit`, `fetch`, …). */
function officeToolKind(kind: string | undefined): ToolKind {
  switch (kind) {
    case "read": case "search": case "skill": case "write": case "shell":
      return kind;
    case "execute":
      return "shell";
    case "edit": case "delete": case "move":
      return "write";
    default:
      return "other";
  }
}

this.emit(
  state,
  "tool.started",
  { toolCallId: update.toolCallId, title: update.title, ...(update.toolKind === undefined ? {} : { kind: officeToolKind(update.toolKind) }) },
  turn.turnId,
);
```

`skill.read` calls `handlers.onSkillRead(name)` after a successful read; `EngineManager` emits `skill.loaded` from `skillIndex`. Native's own path already reports skill reads through `skillNameFromRawInput` (`rawInput.path === "skill://<name>"`), so the handler is only needed for engines that read skills through a tool call without a path.
