# M3.0 Tool Broker (MCP Client) Design Specification

## 1. Goal

Provide a robust local Tool Broker in NoirHarness implementing the Model Context Protocol (MCP) client specification over `stdio`. It connects external MCP servers, dynamically discovers tools, translates them into engine-executable schemas, enforces agent permission policies, and handles process lifecycles across both Native and ACP engines.

## 3. Stdio JSON-RPC Client (`packages/kernel/src/mcp/`)

### 3.1 Framing & Protocol
- Transmitted as UTF-8 newline-delimited JSON strings (`\n`).
- Initialization sequence:
  1. `initialize`: sends `{ protocolVersion: "2024-11-05", capabilities: {}, clientInfo: { name: "NoirHarness", version: "0.1.0" } }`.
  2. Receives result; sends notification `notifications/initialized`.
  3. Queries `tools/list`: returns array of `{ name, description, inputSchema }`.
- Execution:
  - Calls `tools/call` with `{ name, arguments }`.
  - Parses result `{ content: [{ type: "text", text: "..." }], isError?: boolean }`.
- Timeouts:
  - 10 s deadline for handshake and discovery.
  - 120 s default per tool call (bound to session turn timeout).

### 3.2 Error & Lifecycle Guarantees
- Subprocess spawned with unbuffered stdio pipes.
- Stderr captured into ring buffer (max 64 KiB) for diagnostic output upon exit or error.
- Process lifecycle tied to session:
  - Child processes killed via `SIGTERM` when session finishes or aborts.
  - Forced escalation to `SIGKILL` if process does not exit within 3 seconds.

## 4. Engine Integrations

### 4.1 Native Engine
1. Kernel resolves active MCP servers for the session (based on agent's `mcpServerIds` or globally enabled).
2. Spawns session MCP clients, runs discovery, and prefixes tool names: `mcp__<serverName>__<toolName>`.
3. Merges discovered tools into native tool registry for prompt construction.
4. When LLM emits `tool_calls` targeting `mcp__*`:
   - Checks permission policy for `"mcp"`.
   - If `"reject"`: returns error message immediately.
   - If `"ask"`: emits `permission.requested` card with tool parameters. Upon user `"allow"`: invokes MCP tool.
   - If `"allow"`: executes directly without prompt.
   - Yields output as `tool.output` and `tool.completed` / `tool.failed`.

### 4.2 ACP Engine (`omp acp`)
- Formats enabled MCP servers into ACP `session/new` payload parameter `mcpServers`.
- `omp` manages subprocesses through its native ACP transport.

## 5. UI Surfaces

### 5.1 Setup View
- **MCP Servers** panel:
  - List of servers with name, command, argument summary, enabled switch, Test, Edit, and Delete actions.
  - Create/Edit dialog: inputs for Name, Executable Command, Args (list), Environment Variables (key=value).
  - Test button invokes `mcp.test` and renders green badge with discovered tool count or red alert with stderr message.

### 5.2 Agent Config Inspector
- Permission Policy matrix renders **MCP Tools** with `Ask` / `Allow` / `Reject` buttons.
- Server assignment checkboxes: choose which MCP servers this agent can access.
